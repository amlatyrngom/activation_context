Reviewed 22:50–23:05 UTC against the plan, the ledger from 21:00 UTC (A32DLn heads going silent, A32KVSn/A32KVS/NKVSW = control with takeovers ≈ 0) and the training code that the plan reuses (`ac_model_training.py:376–400` paired histories, `:906` per-token teacher/student position lists, `:1130–1133` base forward via `decoder_forward(..., lora_name=None)`). No code exists yet; this is a judgement on the design. Read-only.

## Verdict: SOUND (with three items the implementer should fold in; none changes the arms table)

The objective does what the user's reading asks: the writer gets a per-layer, per-position gradient whose target does not move when the reader stops listening. The collapse mode that killed the residual and K/V heads ("write nothing" is a fixed point of the terminal loss once the reader ignores the channel) has no counterpart here, and the one genuine shortcut (a *student-dependent* teacher) is excluded by fixing the teacher to the base model. The three items below are about making the readout honest (what part of the loss decrease is the rows), the `hidden` source's normalisation, and the checkpointing/positions details that would otherwise cost a debug hour.

## Blockers (fold in before delivery)

**B1. Report the distillation loss with the rows blanked, not only with the rows on — otherwise the trajectory is uninterpretable.** With a fixed base teacher there is no collapse, but there is a large *rows-independent* component: the reader LoRA at layers ≤ l can fit the conditional mean of the teacher's attention output given the prefix and the target tokens alone (the K16r1 reader's own drift from the base is part of it, since the teacher is the un-adapted base). That part falls first and fastest, and it falls in the input-only control too. The gradient that reaches the writer is the *residual* (teacher − conditional mean), which is exactly the passage-specific content, so the term gets cleaner over the run — this is a feature — but the widget must separate the two: log `distill_loss` per layer for the held-out panel twice, rows on and rows off (the `deltas_off` panel machinery, or an attention mask over the row positions for the input-only arms). "Rows on − rows off" per layer is the readout that says whether the rows are delivering the passage; the raw curve alone will look like success in every arm.

**B2. The `hidden` source needs per-dimension normalisation, or drop the arm.** Qwen residual streams carry a handful of massive-activation dimensions (two to three orders above the median at every position, not just the sink); `‖h_s − h_t‖² / rms_l²` on the post-layer residual is then dominated by those dimensions and by the token-identity component the student already has for free, and the passage-specific part of the signal is buried. Either normalise per dimension with the teacher's per-dimension RMS over the supervised positions of the micro-batch (detached, with an epsilon), or standardise by a running per-layer diagonal, or keep `attn_out` only. `attn_out` (post-`o_proj`) does not have this problem to the same degree because it is the attention contribution, not the accumulated stream. If the arm stays as written, A32XDH is the one line in the table likely to be a wasted GPU-hour.

**B3. Under the reader's gradient checkpointing the hooked `self_attn` outputs are graph nodes inside the checkpoint frame — test it the round-6 way.** The student hooks fire during the first forward; the loss then reads slices of tensors created inside `GradientCheckpointingLayer.__call__` (non-reentrant), while the terminal loss reaches the same frame through the layer output. That works with non-reentrant checkpointing (round 6's side capture is the same shape and matched to 1e-6), but only if the hook stores a view and saves nothing of its own, and the arms' sequences at `ckpt_min_tokens 1700` will be checkpointed for the longer items and not for the shorter ones, so both paths run in one job. Ship the test that compares checkpointed vs un-checkpointed gradients of the writer (row modules, side LoRA) and of the reader LoRA under `distill_weight > 0`, plus the bit-identity digest at `distill_weight 0`.

## Answers to the six questions

**(1) Training-friendliness / shortcuts.** The plan's argument holds. The shortcut to exclude is a teacher that shares the student's LoRA (then the reader can make attention at the target positions context-independent — attend to the sink — and both sides agree at zero cost); the base teacher on the full history is fixed, so the only ways down are (a) the rows delivering what the passage delivered, (b) the reader fitting the rows-independent conditional mean (B1: real, benign, must be separated in the readout), and (c) nothing else at the writer: the gradient into the row content is non-zero as long as the target positions attend to the rows at all, which the warm reader does through the input channel (1/32 held 0.32 vs a no-context reader far above), and for the `kv_transfer` arm additionally through the spliced K/V at every layer. "Write nothing" is no longer stationary because the term penalises the *reader's* attention output, which the writer can improve whether or not the terminal loss currently cares. One caution rather than a shortcut: an MSE on intermediate activations with insufficient information pulls the student toward hedged (mean) attention outputs, which can cost terminal loss while λ is high; that is what the schedule's decay is for — keep the floor, and read `held` at the end, not at λ's peak.

**(2) The target tensor.** `attn_out` (post-`o_proj`, the residual contribution of attention) is the right default: it is what the residual stream receives, it is invariant to head permutation, it is where "what the passage delivered" lives, and it excludes the MLP's token-local work. Per-head pre-`o_proj` output would let one weight heads, but `o_proj` already weights them by their contribution to the stream, which is the weighting that matters for the terminal loss; per-head normalisation would upweight low-norm heads, most of which are not the retrieval heads. Per-layer RMS over the supervised positions is sufficient for `attn_out`; per-dimension is needed for `hidden` (B2). Two refinements worth one line each: compute `rms_l` over the micro-batch's supervised positions rather than the example's (fewer degenerate values for short targets), and consider extending the supervised positions from the assistant target tokens to the whole aligned suffix after the run (question tokens included, where a QA-shaped reader does its lookup); for reconstruction material the two nearly coincide, so this can wait.

**(3) Reader LoRA at 2e-5.** Capacity is not the limit: the reader LoRA covers q/k/v/o and the MLPs at every layer (`DEFAULT_LORA_TARGET_MODULES`), and the dense term gives it a far better-conditioned direction than the terminal loss. Adam's step size is ≈ lr per parameter regardless of the signal, so 2e-5 over 1,024 updates (Σ lr ≈ 0.01) moves the reader about as far as the input-only control moves it; what changes is that the steps now agree with each other. A separate "q-side term" is not needed — the attention-output match already back-propagates into q_proj at the supervised positions and into k/v at the row positions. If one arm slot is free, `reader_lr 5e-5` on the weight-1 base is a better use of it than weight 3 (see 6).

**(4) λ schedule.** Hold 25 % → linear to a 5 % floor at 75 % → hold is a sensible default: the floor keeps the writer's dense gradient alive to the end (without it the closed loop can re-form in the last quarter), and 1.0 means parity with the terminal term, which the normalisation makes literal at the start. Do not implement the gated schedule now: the trigger quantity (rows' attention share) needs a manual attention over captured q/k with RoPE re-applied at the chosen layers, and a threshold nobody can set before seeing one run; the clocked schedule plus the B1 readout tells you after the first arms where the gate would have fired. If `rows_attention_share` is cheap enough for the held-out panel on a few items, keep it as a widget only.

**(5) Teacher cost and alignment.** Cost: one no-grad bf16 forward of the base over the full history (≈ passage + prefix + targets) — about one third of the side pass's forward+backward and less than the reader's, so +15–30 % step time is the likely band; the plan's +30–40 % is a safe budget. No checkpointing, no stored activations beyond `8 × T × 2560 × 2 B` per example — tens of MB at micro-batch 3. Use the existing base path (`decoder_forward(..., lora_name=None)`, as the live penalty reference does at `:1133`) rather than toggling adapters by hand, and run it outside the reader's intervention-hook context so the K/V-transfer hooks cannot fire on the teacher. Alignment: the plan says "start offsets", but the code already has better — `prepare_training_history` returns per-token position lists for both views (`teacher_positions`, `student_positions`, equal length because both come from the same `assistant_token_ids`; the KL loss already zips them at `:906`). Use those, not offsets. One wiring point: `build_example` only tokenises the teacher view when `loss_kind == "kl"` or for the penalty reference (`:383`); the SFT arms need the `distill_weight > 0` branch added there, and the material does carry `in_context_messages` (the study generator builds both views). Caching the teacher tensors across epochs is not worth it (≈ 100 GB for 8,192 items at eight layers); recompute per step.

**(6) The arms table.** Nothing wastes a GPU-hour except A32XDH as written (B2). Bases are right: A32X/WCn for the `…n` twins on the K16 init and A32W/WCa for ORCD on K16r1 — pair each arm with its own init's control in the read line, as the plan does. Weight 3 (A32XD3) is the least informative line: if weight 1 moves the rows it will show in B1's gap, and weight 3 mostly tests how much terminal loss the hedging costs; if a slot is scarce, replace it with `reader_lr 5e-5` at weight 1. A32KVTAD is worth running regardless of A32KVTA's outcome (the dense term is exactly what would make the takeover matter); keep it behind A32KVTA in the queue so the two are read together. The decision gate (ceilings first, else the seed run) is right: this objective is the same code in both places, and a warm reader that has already settled on the input channel is the harder test.

## Notes

- N1. Log λ and the per-layer `distill_loss` on the schedule clock, and put the rows-off twin (B1) on the same plot.
- N2. `distill_layers` default = the intervention layers when configured: for the kv_transfer all-layer arm that is every full-attention layer anyway; for the input-only arms `-1` is right. Do not include layer 0 or the last layer's attention if `-1` is ever extended beyond full-attention layers.
- N3. Bit-identity at `distill_weight 0`: no teacher tokenisation, no hooks, no extra optimizer group; the digest run as in rounds 5–6.
- N4. The term is a mean over layers; with eight layers of equal weight the shallow layers (whose attention output is mostly local) contribute as much as the deep ones. Fine for the first arms; a per-layer weight is a one-line follow-up if the deep layers turn out to carry the gap.
