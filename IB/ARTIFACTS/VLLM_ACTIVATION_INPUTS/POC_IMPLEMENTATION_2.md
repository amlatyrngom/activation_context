## Part 1 — training-review fold-in (`POC_TRAINING_REVIEW.md`, REVISE)

1. **Relative scale parametrisation + own group.** `DeltaHead` now holds a buffer `rms` (the layer's calibrated residual RMS) and a parameter `relative` (initialised to `intervention_scale_fraction`, default **0.05**); the applied scale is `rms × relative` (`head.scale` is a computed property). `KVDeltaHead` has `rms_k`/`rms_v` and `relative_k`/`relative_v`. Calibration writes the RMS into the heads (and the `intervention_calibration` buffer, kept for summaries) and never touches `relative`. In `train()` the relative scales are removed from the encoder group and always form the **last** optimizer group at `learning_rate_delta_scales` (default 1e-3): one Adam step moves every layer's scale by the same share of its residual. The old `learning_rate_gates_scope="delta_scales"` is gone (config validation names the remaining scopes); `NDIg` now means `delta_scale_lr 3e-3` on the new parametrisation. Checkpoints save `relative` and `rms` per head; **a checkpoint written with the old absolute `scale` (`scale_k`/`scale_v`) converts on load**: `relative = scale / calibration RMS`, `rms = calibration RMS`, logged per layer ("Converted the checkpoint's absolute delta scales…"); refused only if such a checkpoint carries no calibration. The trace/widget `relative` is now the parameter itself; the summary reports `scales` (absolute), `relative`, `scale_fraction`, `parametrization: "relative"`.
2. **Input-only → deep migration in `load()`.** A checkpoint without intervention fields loading into a deep model: the shared modules load (`strict=False`, and the missing keys must be exactly the deep ones, nothing unexpected), the heads keep their seeded fresh init, `interventions_calibrated` is cleared and `train()` calibrates on the warm reader before its first update; logged "Migrated an input-only checkpoint into a deep model…". A deep checkpoint whose layers differ from the configured ones is still refused, in both directions, and a deep checkpoint never loads as input-only. This is what `init_ac`/`init_reader` from K16r1 with `interventions 4` needs.
3. **Controls.** `intervention_heads_frozen` (arm `heads_frozen`, arm `NDIR`): the heads' `up`/`down` leave `trainable_parameters()`; only the relative scales train. `intervention_detach_source` (arm `detach_source`, arm `NDID`): the heads read `source.detach()`, so the deltas' gradient stops at the heads and the encoder / side adapter hear only the input row. Both are no-ops for an input-only model (tested).
4. **Guards / logging.** `encode_batch(with_layers=False)` (and therefore `encode()` and the rollout queue) raises for a deep model instead of silently dropping the deltas; the encoder's own child-row calls use `with_layers=True`. `capture_layer_input_rms` now records the **median over positions with the first token excluded** (one value per sequence, averaged over the eight calibration sequences); the reader hooks write the residual RMS **at the row positions** of every training forward into the payload (`row_rms`), which the trainer harvests and traces per layer (`intervention_row_rms` widget: the deltas' true denominator, reader as trained, rows present); the encoder records the cosine between each layer's delta and `target_head(z)` per encoded batch, traced and plotted (`intervention_cosine` widget; residual targets only — K/V deltas live in another space); the head-norm widget is re-captioned ("proportional to the scale by construction… tracks the scale walk, not learning"). Neither readout costs a forward.
5. **Warm-started arms.** `NDIW`, `NDILW`, `NKVW` = the arm + `init_ac`/`init_reader` from K16r1 epoch 2 (the `A4X`/`WCa` paths); peak LR left as the arm's (`encoder_lr` is already an arm key → `learning_rate_ac` overridable). `NDIAW`/`NDIALW` follow with phase F.

Deferred from the review: the gradient-into-`rows` per head (five `autograd.grad` calls per trace; needs a dedicated micro-batch) and the attention-mass readout (eager attention) — both need an extra forward, excluded by the brief; the per-item `deltas_off − held` distribution in `result.json` (bench-side; the panel already has `per_item`); the per-row gate arm.

## Part 2 — A1 layer-matched side readout (`intervention_source = "side_layers"`)

Head *l* reads the side model's hidden state **at the input of side layer s(l)** (HF's `hidden_states[s]`) at the memory-row positions, instead of the final normed state `z` that also makes the input row. `s(l) = l` unless `intervention_source_layers` maps otherwise (validated: one side layer per intervention layer, within the side depth). Capture = pre-hooks on exactly the needed side layers during the one side forward (`capture_layer_input_rows`): graph-attached row slices only, removed right after the forward (non-reentrant checkpoint recompute never re-captures). Everything else (heads, init, calibration, checkpoint fields, `RowCache`, queue, `deltas_off`) unchanged; zero new parameters, payload unchanged.

## Part 3 — B1 additive pre-RoPE K/V deltas at the rows (`intervention_target = "kv"`)

Per intervened layer one `KVDeltaHead` = `Linear(d_side, r) → SiLU → Linear(r, 2·d_kv)` split into `dk`, `dv` ([M, d_kv], `d_kv = num_key_value_heads × head_dim`, 1024 on Qwen3.5-4B), each unit-RMS per row × `rms_{k,v} × relative_{k,v}`; calibration measures the reader's own K RMS (after `k_norm`, before RoPE) and V RMS (after `v_proj`) on the same sequences (`capture_kv_rms`). Full-attention layers only (construction and hook both refuse others). Reader side: the decoder-layer pre-hook stashes the bound payload on the layer when it carries `kv_inputs` for that index (and resets the stash at every layer forward — an early-stopped checkpoint recompute skips the clearing hook, found by the training tests); forward hooks on `self_attn.k_norm` (output [B, S, H_kv, D], **before `apply_rotary_pos_emb`** — verified in HF 5.15.1 `Qwen3_5Attention.forward` / `Qwen3Attention.forward`) and `self_attn.v_proj` add the rows out of place at `positions − offset`. Generation: same binding as the residual path (prefill only). The residual stream at the rows is untouched (tested). NKV's source is the layer-matched readout; `summary` allowed. Parameters at r = 640: ≈ 2.95 M per layer (residual head ≈ 3.28 M); payload 4,096 B per row per layer (residual 5,120 B). **Not done:** the attention-mass readout (needs eager attention + `output_attentions`).

## Deviations / decisions

1. **Absolute-scale checkpoints convert** (not refused): `relative = scale / rms`; only a checkpoint with an absolute scale and no calibration is refused.
2. **Calibration** stays on the eight no-row stripped-history sequences (median over positions, first token excluded); the residual RMS **at the row positions** is measured on the training forwards and traced/plotted instead of being used as the calibration denominator (the rows do not exist before the heads are calibrated).
3. **Cosine readout** is against `target_head(z)` (the input row), per encoded batch, residual targets only; the row-RMS and cosine readouts are two new widgets next to `interventions` rather than extra series inside it (different units).
4. **K/V head initialisation**: the residual heads' construction (random bottleneck, unit rows, relative scale at the fraction), not a zero `down` (`unit_rows(0)` is undefined).
5. **`gates_scope "delta_scales"` removed** (the delta scales always have their own group); `NDIg` rewritten accordingly.
6. `ModelDescription.d_kv` added (one more product file); `arms.json` hunk against `/workspace`'s current file.
7. The K/V stash reset (stale-stash bug) and the migration's `strict=False` key check are product fixes found by tests during this phase.
