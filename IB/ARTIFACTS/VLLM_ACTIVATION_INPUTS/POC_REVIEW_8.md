## Checks in the requested order

**(1) The side K/V capture.** `capture_kv_rows` (`hf_utils.py:357–385`) registers forward hooks on `self_attn.k_norm` and `self_attn.v_proj` of the chosen side layers. In transformers 5.15.1 `Qwen3_5Attention.forward` computes `key_states = self.k_norm(self.k_proj(h).view(hidden_shape)).transpose(1, 2)` and applies `apply_rotary_pos_emb` afterwards, so the `k_norm` output is `[B, S, H_kv, D]` — post-norm, pre-transpose, pre-RoPE, before the GQA `repeat_kv` inside the attention function; `v_proj` gives `[B, S, H_kv·D]`. The hook slices `output[row, start:end].reshape(end − start, −1)` → `[M, H_kv·D]` in the side dtype (bf16). The reader hook (`add_rows`, `:189`) reshapes the contribution back to `(−1, *output.shape[2:])`, i.e. `[n, H_kv, D]` for K and `[n, H_kv·D]` for V — the same layout because side and reader are one loaded model (`ac_model.py:317–318` refuses otherwise). The test compares the payload with a plain-hooked un-checkpointed side forward with `torch.equal`. Positions: `_transfer_span` (`:885–890`) takes the summary rows `[N, N+V)` of the side sequence `[content | summaries]` (`:757–769`), i.e. exactly the rows whose final states also make the input rows. Graph attachment under the side's non-reentrant checkpointing: the hooks fire during the first forward inside the checkpointed layer and store views; they save no tensors of their own and are removed before backward, so the recompute reproduces the same saved-tensor sequence and the views' backward unpacks correctly (checkpointed vs direct gradients of the takeovers and of the side LoRA agree to 1e-6 in the test). Memory: the views pin the `k_norm` / `v_proj` output tensors of the captured layers (`[B, S, d_kv]` bf16 ≈ 11 MB each at B = 3, S ≈ 1,800), so ≈ 22 MB per captured layer, ≈ 180 MB for the eight-layer arms — not the whole side activations. See finding 1 for the copy that *is* avoidable.

**(2) Bit-identity of existing configurations.** Mechanism, not just the digest: the K/V capture is `nullcontext()` unless `kv_transfer` (`ac_model.py:792–794`); `row_spans` and the `capture_layer_input_rows` call are unchanged otherwise (`:798`); `resolve_intervention_layers` only adds the `−1` branch (`ac_model_utils.py:747–750`); `_resolve_layers` returns early only when `intervention_layers` is set (`:427–431`); `validate_part_capacity` now calls `num_view_rows(len(ids), ratio)` on the same `ids` that `part_view_rows` would have tokenised with the same child lengths (`ac_model_utils.py:227`), so the number is identical; `part_view_rows` → `run_rows` equals `num_view_rows` unless `kv_transfer_full` (`ac_model.py:347`); `_refuse_nested_parts` is a no-op unless full (`:353`); the trace/summary `kv_replacement` branches produce the same fields for `kv_slots` as before; `KVSlotHead`/`KVDeltaHead`/`DeltaHead` are untouched; no state-dict key appears unless a transfer target is selected. Input-only, scaled, lora, `kv`, `kv_slots`, `passage_attention` and `cross_attention` models therefore run the same code as at `5325675`; the implementer's digest run agrees.

**(3) t = 1, the takeover, the correction.** At t = 1 without correction `content = 1.0 · side.float()` and `keep = 0`, so the reader writes `(own.float() · 0 + content).to(bf16)` = the side's bf16 K/V exactly (tested with `torch.equal`); other positions untouched at the first spliced layer; deltas-off = no payload = the reader's own K/V. Takeovers are the head's `scale_parameters()` (`ac_model_utils.py:733`), the last optimizer group at `learning_rate_delta_scales = 1e-3` (three groups, tested); Σ lr over the arms' 1,024-update cosine ≈ 0.5, so t can move from 1.0 to ≈ 0.5 within the pass — well-scaled for the question asked (does the reader want its own K/V back?), and bounded away from sign flips. The correction (`intervention_transfer_correction`, off in every arm) is lora-style with `down = 0` and no unit-RMS normalisation or learned scale on its own path, so the round-3 collapse (scale gradient ∝ 1 while the head's ∝ scale) has no counterpart; its only multiplier is the takeover itself, which starts at 1 and cannot reach 0 in a pass. `intervention_detach_source` detaches the captured K/V (`:860`), so the control is honest.

**(4) Generation / decode.** The payload is the `kv_slots` entry, so `generate_with_interventions`, the cache-offset binding, the prefill write and the decode no-op are round 5's without change; the test checks the first generated step's logits against the training forward and greedy decoding against a full recompute. The rows' cache entries hold the transferred (then rotated) K/V.

**(5) `kv_transfer_full`.** `run_rows` returns `max(N, V)` only for this target (`ac_model.py:347`); `part_view_rows` uses it, so the study generator, the trainer's spans and the assembly assert all see R placeholders per part (tested); `input_embeds` are the V rows followed by `R − V` zero rows (`:823`); `_transfer_span` is `[0, max(N, V))`, so passage token j's own K/V land on run position j (tested with `torch.equal` against a manual side forward, in order). Pooling is refused at config time (`:187–188`), nested parts at `part_view_rows` and `_encode_requests` (`:353`, `:679`), `measurement_only` is in the summary and the checkpoint, the bench summary line says "CEILING MEASUREMENT (not a candidate)", and the arm notes carry the phrase (tested). The deltas-off control for the ceiling is the reader's own K/V over the same R-long run (rows + zeros), not the plain input-only run — finding 3.

**(6) Save / load.** `intervention_summary()` (saved with the modules) carries `target`, `takeover`, `transfer = {init, correction}`, `measurement_only`; `load()` refuses a target mismatch through the existing `source/target` tuple (tested against `kv_slots`, `kv`, `kv_transfer_full`) and a correction mismatch (`:970`); `_convert_absolute_scales` returns early for the new targets; migration of an input-only checkpoint leaves the takeovers at their init and calibration pending (the `deep_keys` set is the takeovers and anchors, or plus the correction's `up/down`). `intervention_transfer_init` is deliberately not compared on load — a checkpoint carries trained takeovers, so the init no longer matters.

**(7) vLLM parity.** Unchanged from `kv_slots` and still plain: per request and per spliced layer, M rows of `(k, v)` bf16 plus two per-layer scalars of model state; the write `k[idx] = keep_k·k[idx] + rot(t·k_side)`, `v[idx] = keep_v·v[idx] + t·v_side` at the seam after the K/V projections and before the attention op, into the row positions' cache entries; decode needs nothing. What is new is on the *encoder* side: the payload's content is the side model's own post-`k_norm` K and post-`v_proj` V at the rows, which the encoder pass has to emit alongside the rows — a hook-shaped extra output of the side forward, the same seam as the reader write. Nothing position-at-a-time, no kernel or scheduler change. `kv_transfer_full` is not engine-compatible by design (the run is the passage length) and is fenced as such.

**(8) Efficiency of the capture.** Per captured layer: two view slices per physical row (no copies) and, in the encoder loop, one fp32 copy of `[V, d_kv]` per example per layer (≈ 130 KB at V ≈ 110, 1/16) — negligible for NKVTWA's eight layers. The full arms copy `[R, d_kv]` (≈ 7 MB) per layer per example and ship `R × d_kv × 2` bf16 per layer per part (≈ 55 MB at eight layers), as the write-up states. The avoidable cost is finding 1.

## Findings

**1. LOW — The side layer inputs are still captured and copied to fp32 when the correction head is off.** `kv_transfer` requires `intervention_source = "side_layers"`, so `capture_layer_input_rows` runs on the same spans (`ac_model.py:796–801`) and the loop takes `source = captured[...][row].float()` (`:837`) for every layer — `[V, d_side]` fp32 per layer per example for the row arms (small), but `[R, 2560]` ≈ 17 MB per layer per example for the full arms (≈ 420 MB per micro-batch at eight layers) and the views pin the eight layers' input tensors (≈ 28 MB each) — all unused when `head(source)` returns `None` (`:862–863`). Fix: skip the source capture and the `.float()` when `not head.correction` (build `row_spans`/the `capture_layer_input_rows` context only if the correction is on, or compute `source` lazily inside the `correction is not None` branch). Not a correctness issue; the arms fit on the 96 GB cards either way.

**2. INFO — The full arms roughly double the reader sequence.** With R = N the reader sees `prefix + R placeholders + N target tokens` ≈ 2N + prefix (≈ 3,500 tokens at N ≈ 1,700) at `micro_batch 3`, all under reader checkpointing (`ckpt_min_tokens 1700` is met). Expect the ceiling arms to run at roughly half the step rate of their row twins and to need more activation memory; budget accordingly (the 27,000 s budget may truncate the epoch — read `held − deltas_off` at matched update counts).

**3. INFO — What the ceiling's deltas-off is.** For `kv_transfer_full`, deltas-off is the reader's own K/V over the R-long run (V rows + zero rows), not the input-only run of V rows: the zero rows contribute nothing at layer 0 (RMSNorm of 0) but occupy positions and attract attention mass at every layer, so the ceiling's control may sit slightly off the input-only line; compare NKVTF / A32KVTF against their own deltas-off first, and against A32X / WCn second.

**4. INFO — `intervention_slot_rms` for `kv_transfer` reads ≈ the side/reader K/V RMS ratio at init, not 1.** The widget text says so (`ac_model_reporter.py:177–182`); noting it here so the first trace point is not read as a departure.

## Verdict: APPROVE

Findings: 1. Side layer inputs captured and copied without a correction head (LOW) — 2. The full arms roughly double the reader sequence (INFO) — 3. The ceiling's deltas-off is the R-long run (INFO) — 4. `intervention_slot_rms` starts at the side/reader RMS ratio for transfers (INFO).
