# Deep interventions — architecture candidates that fit both HF training and the pinned vLLM fork

Investigation written 2026-09-16 against the working tree (POC applied, tag `ac-recon-20260916T155942Z`) and the submodule at `IB/REPOS/vllm` (v0.28.0, `2cf0a69`). Read-only: nothing in `activation/`, the bench or the fork was changed. Line numbers are those observed today and will drift; symbol names are the durable anchors. "Row" means one memory row (one compressed position, ratio 1/16 or 1/4) that the renderer writes over a placeholder token in the reader's prompt. Qwen3.5-4B facts used for byte counts: hidden 2560, 32 blocks, full attention at 3,7,…,31 with 4 KV heads × 256 dims (K+V = 2048 values per token per full-attention layer), gated DeltaNet (GDN) elsewhere with 32 value heads × 128 × 128 recurrent state per layer and a conv kernel of 4.

## 0. Summary and ranked recommendation

**The evidence points at the encoder, not at the injection mechanism.** The first deep run (NDI vs NDC) says the five residual deltas are worth ~0.008 nats at epoch 0.125 while the shallow scales climb from 1 % to 9 % of the residual RMS in 200 updates: the reader pulls hard on the deltas and gets almost nothing, which is what you expect when every delta head is an FFN of the *same* summary vector `z` that already produced the input row (`ac_model.py:_encode_prepared_batch`, `rows = hidden[row, end-num_rows:end]` feeds `target_head` and every `delta_heads[l]`). A function of `z` cannot carry information that `z` does not; it can only re-present it per layer, and the reader's own attention and MLPs already re-present the input row per layer. Reconstruction errors at 1/16 are content-level (specific digits, names, identifier order — `AC_RECON_RESULTS.md` finding 11): a bandwidth problem, i.e. bits per row, not a depth-of-injection problem. Anything that increases the *distinct* information per row is worth more than any new way of adding the same vector.

That yields the ordering. Everything in tier A changes only what the heads read and needs **no** engine change (the payload shape is unchanged); tier B and C need fork work but stay one-shot and prefix-cache-compatible; tier D breaks one of the hard constraints.

**Recommendation.** (1) Let NDI/NDIg finish and read `held − deltas_off`. (2) Run A1 (layer-matched readout) as the next HF-only arm — it is a one-line change in what the heads consume plus `output_hidden_states` plumbing, pairs exactly with NDC/NDI, and directly tests the hypothesis that the deltas are starved of *new* information. (3) If A1 helps, A2 is the natural generalisation; if it does not, the row bandwidth is the limit and deeper injection of any kind is unlikely to pay — spend on ratio/row count instead. (4) Only then build engine-side mechanisms, in the order B1 → C1 → C2, each first as an HF-only bench arm; all three keep the settled payload contract (immutable per-row tensors, one-shot encode, per-block hash of the bytes) and differ only in which reader tensor the bytes touch. Do not build D1–D6.

## 2. Candidates

### 2.1 What the delta heads read (encoder side; no engine change)

**A1 — layer-matched side readout.** Today every head reads `rows` = the side model's *final* hidden state at the summary positions. The side model is the same Qwen3.5-4B (+ `rag_side` LoRA); its per-layer hidden states at those positions are computed anyway and discarded. Let head *l* read the side state at layer *s(l)* (start with *s(l) = l*: same architecture, same depth; the residual stream at depth *l* is the natural "what layer *l* of a Qwen3.5 knows about this passage"), optionally concatenated with `z` (`Linear(2d, r)` first layer). Payload unchanged. One-shot: yes (function of the passage only). HF change: `LoadedModel.decoder_forward` must be able to return `outputs.hidden_states` (pass `output_hidden_states=True` through to the HF decoder; `Qwen3_5TextModel.forward` collects them through `TransformersKwargs`), `_encode_prepared_batch` slices `hidden_states[s(l)][row, end-num_rows:end]` per head. Under `side_gradient_checkpointing` the tuple of 33 × [B,S,2560] fp32/bf16 states is held for the backward; at the reconstruction shapes (≤ 2 k side tokens, micro-batch 3) that is < 1 GB. Training friendliness: unchanged heads and init; the calibration (1 % of residual RMS) stays. Prefix cache/replay: unchanged (bytes are what is hashed). **Why it can matter:** the summary positions' final state is the output of a decoder that was trained to predict the next token; intermediate layers keep more surface detail (exact digits, names) that the final state has already abstracted — precisely the class of errors the reconstruction panel shows. Cost: zero new parameters, no new bytes.

**A2 — per-layer passage attention in the encoder.** Head *l* becomes a query module: the row's summary state (or its layer-matched state) attends over the mixed passage token states (`mixed = x[row, :length]` after the mixer, or `content`) and the result feeds `DeltaHead`. This is `AdaptiveSummaryPooling` per layer without the fixed bins (or with them). One-shot, payload unchanged. Cost: one attention over ≤ 2 k keys per row per layer per encode — negligible next to the side forward. Training: a fresh attention block has the "silent phase" problem the ledger documents for random heads (finding 2): initialise the query path as the identity of the existing summary (zero-init the attention's output projection so head *l* starts exactly as today's head) and let it open. Bytes unchanged; the gain is that each layer can select *different* passage content for the same row, which a function of one `z` cannot.

**A3 — reader-conditioned encoding** (encoder reads the reader's state at the row positions). Rejected: needs a reader forward before the encode, per request, and the encoded rows then depend on the whole prefix (system prompt, earlier tool outputs) — the row cache (`RowCache`, keyed by part content) and record replay stop working, and vLLM would need a two-pass request. The reader-conditioned *combination* is available without that cost in C1 (module inside the reader).

### 2.2 B1 — additive K/V at the memory-row positions (full-attention layers)

Definition: for each intervened full-attention layer *l* and each row, the encoder emits `dk_l, dv_l` ([M, 4×256] each, pre-RoPE, learned scale included). The reader computes its own K/V at the row (with its LoRA) and adds the deltas before RoPE (K) and before the cache write (V). Nothing else at the row changes; the row's residual stream is untouched. Later tokens read the rows through their own queries.

Why rows and not virtual slots: the rows already occupy real prompt positions, so the scheduler, block hashes (`hash_block_tokens` over token ids + `prompt_embeds` bytes), `slot_mapping`, `positions_np` and RoPE all work unchanged. Virtual slots would have to become tokens (`Request.num_tokens`, `NewRequestData.prompt_token_ids`, `seq_lens`) and the GDN layers have no slot notion at all (`MambaSpec` is one state per request, updated by every token through the conv and the delta rule).

vLLM: transport and staging are exactly the planned residual-delta path (payload retained in `CachedRequestState`, rows of the current chunk gathered as `(flat_indices, rows)` per layer). Application seam: `Qwen3NextAttention.forward` (:385–397) after `_project_qkv_gate` and before `self.attn(q, k, v)` (:392): `k.index_add_(0, idx, rot(dk))`, `v.index_add_(0, idx, dv)`, where `rot` applies the layer's `rotary_emb` at `positions[idx]` (RoPE is linear, so rotating the delta and adding post-RoPE equals adding pre-RoPE; this avoids touching the fused qkv/norm/rope branch of `_project_qkv_gate`). The modified K/V then flow through `unified_kv_cache_update` → `reshape_and_cache_flash` unchanged, so chunked prefill (rows written when their chunk runs), preemption/recompute (payload immutable, recomputed identically) and prefix caching (the block hash must include the K/V bytes + layer ids + op version exactly as planned for deltas, `_gen_interventions_extra_hash_keys`) all hold. FP8 KV: `reshape_and_cache_flash` quantises with the layer's static `_k_scale/_v_scale`; injected values outside the reader's own K/V range clip, so calibrate `dk/dv` scales as a fraction of the reader's K/V RMS per layer (same `capture_*` pattern as the residual calibration) and report the ratio. GDN layers: not supported for B1 (the conv mixes 4 neighbouring positions and the delta rule has no K/V slot); use residual deltas there if wanted. The attention kernel is untouched. Cost per step: two `index_add_` on [num_tokens, 1024] plus one small RoPE call on the rows — trivial.

HF: forward hooks on `layer.self_attn.k_norm` (output [B,S,H_kv,D], before `.transpose` and RoPE) and `layer.self_attn.v_proj` (output [B,S,H_kv×D]) that add the rows at `positions − offset`, bound by the same `BoundInterventions` kwargs mechanism (the hook needs the payload: keep the existing decoder-layer pre-hook to *stash* the bound payload on the layer for its attention sub-hooks, or read it from the layer kwargs which `Qwen3_5DecoderLayer.forward` passes through `**kwargs` into `self_attn`). PEFT: `k_norm` is a plain module (no LoRA) and `v_proj` is the LoRA-wrapped `lora.Linear`; hooking their outputs is adapter-agnostic. Gradient checkpointing: the hooks run inside the checkpointed layer call, so recompute re-adds the same tensors (the POC review verified this for the pre-hook). Cache offset logic and `generate_with_interventions` are reused unchanged.

Training: gradient path reader-attention-weights → `dk`, values → `dv` — the shortest of all candidates (no norm, no MLP in between). No-op start: zero-init `down` of the K/V heads and calibrate the scale; the learning readout is direct (attention mass from target tokens onto rows at layer *l*, obtainable in HF with eager attention on a few panel items). Expressivity vs residual deltas: a residual delta at layer *l* also changes K/V at *l* (through the input norm and the LoRA'd projections) *and* the row's own carried state; B1 gives the head direct control of what the row *writes* without perturbing what it *carries* or the row's RMSNorm statistics (a large residual delta renormalises the row's own content). It is not strictly more expressive, it is cleaner and easier to train; it does not dominate. Bytes: 4,096 B per row per layer vs 5,120.

### 2.3 Shared in-reader modules (LoRA-like sharing)

Contract: a torch module `f_l(h_rows, p_rows) -> update_rows` (returns the additive update, not the new vector: the fused vLLM residual makes "add to one summand" the natural op, and a pure-additive contract is what keeps `hidden_states[idx] += f(...)` correct in both frameworks; "replace" is `f = p − h`). Parameters live in `ActivationContextModules` (new `intervention_modules: nn.ModuleDict` keyed by layer, saved with `modules.pt`, in the head/scale optimizer group), so ACTrainer updates encoder + module + reader LoRA jointly; AgentTrainer replays frozen payloads and freezes the module (it is AC-model state, like the encoder). Interventions carry `intervention_name` (`"<ac_model_name>_v<version>"`) instead of weights.

- **C1 gated add**: `u = σ(W_g [h; p] + b_g) ⊙ (W_p p)` with `W_p` initialised to the identity and `b_g` to the calibrated small value (not 0: a zero gate is a scalar walk of ~lr per step, the ledger's silent phase). The reader decides per row and per channel how much of the payload to take, conditioned on its own state at that layer. Cost: two [2560×2560]-class matmuls over the rows only. In the fused vLLM loop the module must see the true stream `h = hidden_states[idx] + residual[idx]` (at layer *l* > 0 `hidden_states` is the previous MLP output and `residual` the running sum) — same value the HF hook sees as `args[0]`.
- **C2 row cross-attention over a bank**: payload carries *n* vectors per row per layer; the row's state queries them (softmax over *n* keys, output projection zero-initialised). Only worth it when *n* > 1 carries genuinely different information (it is A2 moved into the reader with the bank shipped instead of computed); bytes × *n*.
- **C3 concat-FFN**: C1 without the multiplicative structure; no reason to prefer it.
- **C4 self-attention over rows inside the reader**: rejected (D5): if row *i* reads row *j > i*, the block containing *i* depends on later content, breaking causal block hashing, chunked prefill and preemption/recompute. Row-row mixing belongs in the encoder (`mixer`), where it is already bidirectional and one-shot.

vLLM batching (compare punica): punica stacks every active adapter's A/B in slots (`activate_adapter`), builds `_token_lora_indices` for *all* scheduled tokens (`_update_base_metadata`) and runs one shrink/expand Triton kernel per linear layer (`add_lora_linear`), because LoRA touches every token. An intervention module touches only the rows of the current chunk that carry a payload (tens to a few hundred per step), and a step holds at most a handful of distinct `intervention_name`s. So the right shape is *not* a kernel with per-token slot indices but: per step, per layer, group the scheduled rows by name → for each group, gather `h[idx]`, run the module once on the group, `index_add_` back. This is one Python loop over ≤ (number of distinct AC models in the batch) with three small ops each, done at the same seam as the deltas (`Qwen3NextModel.forward` before the layer call, :648). Multi-adapter serving is then natural: two AC models in one batch = two groups; each request also carries its reader `lora_request` as today. Memory: one module per (name, layer) resident, ~13 M params for C1 at 2560 (26 MB bf16 per layer, 130 MB for five layers) — an LRU like `LRUCacheWorkerLoRAManager` (:244) with a small capacity. Latency: negligible eager; CUDA graphs would need a fixed max-rows buffer and one graph per module set — not in the MVP (graphs are already excluded for intervention engines).

Loading in vLLM: the LoRA loader accepts only PEFT layouts (`from_local_checkpoint` insists on `adapter_model.safetensors` and known target modules), so a module needs its own tiny loader: an `InterventionModuleRequest(name, int_id, path)` msgspec struct mirroring `LoRARequest` (equality by name, so `set()` grouping works), a worker-side registry that `torch.load`s `intervention_module.pt` once per replica, and the module *class* vendored in the fork (`vllm/model_executor/layers/interventions.py`) with the same code as `activation/common/intervention_modules.py` — a dependency-free file (torch only) whose kinds are enumerated (`gated_add_v1`, `row_cross_attn_v1`) and whose `CODE_VERSION` is part of the checkpoint and of the cache key. A CPU test asserts the two files are byte-identical.

Prefix-cache identity: block extra keys gain (`intervention_name`, `CODE_VERSION`, kind, layer ids) in addition to the per-block payload bytes; the same bytes under a newer module version must miss. Replay: records must pin `intervention_name` (with version) next to the reader LoRA version — with an in-reader module the *effective* reader input is no longer the payload alone. That is the real cost of tier C relative to plain deltas/B1 (whose effective input is fully in the bytes): one more versioned artifact in provenance, exactly like the LoRA.

HF sharing: `module_manager.py` registers the module under the AC model's name (it is part of `register_ac_model`), `save_lora`-style checkpoint folder `AC_MODELS/<ac>/epoch_NNN/intervention_module.pt` (or inside `modules.pt` plus an exported serving file), `exchange_*` bumps the version so `engine_*_request` returns the new name; the decoder-layer pre-hook looks the module up by the payload's `intervention_name` in a process-local registry filled by the AC model (the payload never carries a module object, so records stay serialisable).

### 2.4 Rejected or deferred, with the reason

- **D1 virtual KV slots.** Every vLLM structure that touches KV is indexed by token position: `Request.num_tokens` (scheduling budget), `hash_block_tokens` (blocks of 16 token ids + extra keys), `slot_mapping` (built from block tables and positions), `seq_lens`, RoPE positions from `positions_np`. Extra entries must be tokens; then they *are* the rows (B1). The `KVConnectorBase_V1` path (external KV loaded into allocated blocks, `get_num_new_matched_tokens` → `start_load_kv`) is the only sanctioned "write external K/V" seam and it also counts tokens; it would let an *external* producer fill the rows' K/V at every layer, but it has no per-layer selectivity, cannot coexist with the reader computing those positions, and adds a connector process — far heavier than B1 for the same effect. HF: `DynamicLayer.update` concatenates, so per-layer pre-seeding is mechanically possible, but `Qwen3_5TextModel.forward` derives `position_ids` and masks from `get_seq_length()` (:1168), so M virtual entries shift every real position unless masks/positions are built by hand, and linear-attention layers have no equivalent entry.
- **D2 recurrent-state prefix for GDN layers.** ~1 MiB per GDN layer per request, must be the *initial* state (so the memory precedes the system prompt — no shared-prefix cache reuse and no mid-context placement), and one state cannot represent several parts. HF pre-seed via `LinearAttentionLayer.recurrent_states`; vLLM via the state slot in `MambaSpec` before prefill with `has_initial_state`. Not worth it against rows that sit anywhere.
- **D3 per-request low-rank weights.** ~279 KB per layer per request (r = 8 over q/k/v/o); applies to every token of the request, so the system-prompt blocks' KV differ per passage → the block hash must include the weights from block 0, destroying cross-request prefix reuse; punica needs adapters loaded by int id from disk (`_load_adapter`), so "tensor LoRA requests" are a new path; training in HF needs per-example functional LoRA. A position-gated variant (apply only from the first row onwards) rescues prefix reuse but is a fourth mechanism. Defer indefinitely.
- **D4 replacement / multiplicative gating from the payload.** Replacement cannot start as a no-op (the row's own state at layer *l* is discarded) and needs the reader state anyway (`p − h`); a payload-carried gate doubles bytes for what C1 computes from `h` and `p`. Fold into C1.
- **Attention-output / MLP-input placement.** Same information as the block-input delta, but in vLLM the add would sit between `self_attn` and the fused `post_attention_layernorm(hidden_states, residual)` inside `Qwen3NextDecoderLayer.forward` (:533), i.e. a second seam inside the layer for no expressivity gain.

## 4. Payload schema and module-sharing contract (proposal)

```python
class Interventions(TypedDict, total=False):          # activation/harness/hf_utils.py (backend-neutral; vLLM gets a typed twin)
    schema: int                                       # 2 (1 = today's positions + layer_inputs)
    positions: list[int]                              # sorted unique prompt rows (HF: physical-row offsets after collation)
    layer_inputs: dict[int, Tensor]                   # [M, d_model] additive residual deltas, scale included (today)
    kv_inputs: dict[int, tuple[Tensor, Tensor]]       # B1: (dk, dv) each [M, num_kv_heads*head_dim], pre-RoPE, scale included
    intervention_name: str | None                     # C*: "<ac_model_name>_v<version>"; None = plain add
    module_inputs: dict[int, Tensor]                  # C*: [M, n*d_bank] per layer, consumed by the named module
```

Rules: every tensor has M rows; layers absent from a map contribute nothing; `schema` and the sorted layer ids of every map, the tensor dtypes/shapes, and `intervention_name` join the per-block hash (`_gen_interventions_extra_hash_keys`, next to `_gen_prompt_embeds_extra_hash_keys`); `EngineCoreRequest` and `NewRequestData` gain one optional field each (typed, appended, msgspec round-trip proven); `CachedRequestState` retains the whole payload; the runner stages only the current chunk's rows per layer as `(flat_indices, tensors)` grouped by `intervention_name`. Records store every tensor content-addressed as planned (M3) plus `intervention_name` and `CODE_VERSION`.

Module sharing: `InterventionModuleRequest(name, int_id, path)` (msgspec, equality by name — copy `LoRARequest`); `module_manager.py` mints it like `engine_lora_request` (`name = f"{ac_model_name}_v{engine_version}"`, `int_id` from the same counter); checkpoint file `intervention_module.pt = {"kind": "gated_add_v1", "code_version": N, "layers": [...], "d_model": 2560, "state_dict": {...}}` written by `ActivationContextModel.save` next to `modules.pt` and referenced by `exchange_*`; the fork loads it in a `WorkerInterventionManager` (LRU, capacity ≥ number of AC models served) and applies it in the model loop; HF applies the same class from `activation/common/intervention_modules.py` through the existing pre-hook. Training: parameters in `ActivationContextModules.intervention_modules`, optimizer group with the heads, FP32 master weights, bf16 export for serving.

## 5. Minimal-risk POC ordering (HF only, reconstruction bench)

Every arm pairs with NDC (same `SEED`, `initial_hash` equal, `deep_hash` recorded), keeps the `deltas_off` panel, reports clean-subset numbers, and adds the shuffled-bundle control the first time a mechanism shows > 0.05 nats. Replicate variance in onset is large (ledger finding 5): compare end-of-run levels on ≥ 2 seeds before believing a difference below 0.05.

1. **P0 — read NDI, NDIg** (queued). Pass: `held − deltas_off` > 0.02 and NDI < NDC beyond seed noise. If NDIg (fast scale LR) opens the gap and NDI does not, the scalar walk was the limit and every later arm gets the `delta_scales` group.
2. **P1 — A1 layer-matched readout** (`NDI-L`): heads read side layer *s(l) = l* states; everything else NDI. Change: `decoder_forward(..., output_hidden_states=True)` returning the tuple, `_encode_prepared_batch` slicing per head; tests: zero mode unchanged, gradients direct vs checkpointed reach the side LoRA through the intermediate states. Pass: `held − deltas_off` ≥ 2× NDI's at matched updates; fail: no change → the deltas are not information-starved, go to P3 with lower expectations. Variant `NDI-Lz` (concat `z`) if P1 is ambiguous.
3. **P2 — head capacity** (`NDI-4x`: `FeedForward(d, 4d, d)` heads instead of the 640 bottleneck, +130 M params): only if P1 helped, to check the heads are not the bottleneck. Pass/fail on the same readout.
4. **P3 — B1 additive K/V at rows** (`NKV`): payload `kv_inputs` at the five full-attention layers, K/V heads `Linear(2560, 640) → SiLU → Linear(640, 2048)` split into dk/dv, zero-init down, scale = 1 % of the reader's K/V RMS per layer (new `capture_kv_rms`); HF hooks on `k_norm`/`v_proj`. Readouts: `held − kv_off`, mean attention mass onto rows at each intervened layer on 8 panel items (eager attention), K/V scale trajectory. Pass: beats NDI at equal updates or opens the `*_off` gap where NDI did not.
5. **P4 — C1 gated add** (`NGA`): module in `ActivationContextModules`, `intervention_name` in the payload, registry lookup in the hook; identity `W_p`, calibrated gate bias. Readouts: gate mean per layer over time (should leave its init), `held − module_off`. This is the first arm whose serving needs the module registry; keep it HF-only until it wins.
6. **P5 — C2 bank** (`NCA`, n = 4 at width 640): only if P4 wins and bytes are affordable.
7. Engine work starts only for the winning mechanism: B1 needs the planned M3/M4 transport plus the attention seam; C1 needs transport, registry, loader and cache keys.

## 6. Open questions

- Is 0.008 nats at epoch 0.125 simply "too early"? K16's transition happened inside 500 updates because its *input* rows started legible; delta heads start as random unit vectors at 1 % scale, the same starting point that produced the silent phase for input rows. A skip-style init is impossible for deltas (no identity through a bottleneck into a different layer's basis), but A1 gives the heads a *pretrained* basis to start from — the second reason to run P1 first.
- Which side layer should feed reader layer *l*? *s(l) = l* is the obvious pairing for the same base; *s(l) = min(l + k, 31)* (deeper side state for the same reader layer) is a cheap sweep.
- Should GDN-block inputs be intervened at all? Every POC layer is a full-attention block by choice (`prefer_attention_interventions`); B1 cannot target GDN blocks, and a residual delta at a GDN input is smeared by the 4-wide conv across neighbouring rows. Leave GDN blocks out until an ablation says otherwise.
- FP8 KV under B1: the injected K/V must stay inside the static per-layer scales; if calibration shows dk/dv RMS approaching the reader's own K/V RMS, either cap the scale or accept BF16 KV for intervention engines.
- CUDA graphs for tier C need padded fixed-size row buffers and a module set fixed per graph; out of MVP, but the module registry should reserve the buffers now so the eager path and the graph path share the staging code.
- Equal-byte fairness: 1/16 with five deltas (6× bytes) vs 1/8 input-only (2× bytes) or 1/4 (4×) — A4K already learns at 1/4 with a trainable reader. A deep arm must beat the input-only arm at *equal bytes* before the default flips to 4; the ranking above is about which deep mechanism to test, not a claim that any of them beats more rows.
