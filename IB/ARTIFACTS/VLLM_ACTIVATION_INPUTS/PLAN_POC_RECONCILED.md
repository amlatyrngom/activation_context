Model facts used below (local HF config of `Qwen/Qwen3.5-4B`): 32 decoder layers, hidden 2560, hybrid layout with `full_attention_interval 4`: full-attention blocks at indices **3, 7, 11, 15, 19, 23, 27, 31**, the rest gated DeltaNet (linear attention). HF 5.15 decoder layers take `hidden_states` positionally and `**kwargs` flow from the text model into every layer call; the layer computes `residual = hidden_states; hidden_states = input_layernorm(hidden_states)`, so adding a delta to the layer input reaches both the residual and the normalised path, as the plan requires.

## 2. POC scope

The POC trains and evaluates through the HF path only: `ActivationContextTrainer` + the reconstruction bench. Needed now:

- **M1** — delta heads, config resolution, calibration, checkpoint save/load with the new fields, legacy checkpoints load as input-only.
- **M2** — per-forward payload through `decoder_forward`, layer hooks in `hf_utils.py` that compose with `checkpoint_adapter_scope`, and `generate_with_interventions` (greedy, single sequence; the payload bound by wrapping the base model's `prepare_inputs_for_generation` for the call, since HF rejects unknown `generate` kwargs) for the fidelity samples.
- **M5 (HF part)** — `_example_loss`, `_batch_loss`, `_evaluate`, `_sample_completions` and the no-context references/penalty assemble one payload per physical row; optimizer covers heads/scales; reporter diagnostics; bench arms.
- **M6 (CPU gates)** — config/topology, zero mode unchanged, gradients direct vs checkpointed for every head, padded-batch causality/positions, cached vs no-cache generation, checkpoint round trip + resume, calibration; the learning gate is the POC run itself.

Deferred, with the reason:

- **M3 agent records/caches**: the bench never records rollouts; the payload dataclass is designed now so M3 only adds serialisation.
- **M4 vLLM fork**: serving is not on the POC path; nothing in M1/M2/M5 constrains the engine transport beyond the payload shape already fixed in the plan.
- **Packed `[1,S,D]` collation (`agent_training_utils`)**: the bench uses right-padded `[B,S,D]` batches only; packed offsets come with AgentTrainer replay (M5 agent part).
- **FP8 / prefix-cache / IPC gates**: engine-side.
- **Legacy → deep checkpoint migration**: the POC arm starts fresh; the loader only has to treat missing fields as input-only. Migrating K16's epoch-2 checkpoint is a follow-up experiment, not a POC prerequisite.
- **Shuffled-bundle control**: needs equal row counts between donor and recipient items and an eval-only code path; the bench's existing no-context floor (reader without rows *and* without deltas, automatic since stripped histories carry no parts) is the content-removal control the POC reports. Shuffle is the first follow-up.

## 3. The POC run

**Arms** (added to `arms.json`; everything not listed is ND's value):

| key | recipe | purpose |
|---|---|---|
| `NDC` | = ND exactly: `train_items 8192, epochs 1, ratio 1/16, gold_targets, row_head_skip, fresh_initial, micro_batch 3, ckpt_min_tokens 1700, lr_schedule cosine, warmup 50, reporting_interval 0.125, completion_samples 4`, `interventions 0` | paired control, re-run from the new code (proves bit-for-bit equivalence with ND's 0.712 up to kernel nondeterminism, and gives the same-code baseline) |
| `NDI` | NDC + `interventions 4, last_layer_intervention true, prefer_attention true` | the deep arm |
| `NDIg` | NDI + `gate_lr 0.003, gates_scope delta_scales` (the delta scales alone in their own Adam group at the K-recipe gate rate; every shared parameter trains exactly as in NDC) | the second run: are the deltas starved by the scalar's slow walk at 1e-4? |

Resolved layers for Qwen3.5-4B (L = 32, n = 4): interior `floor(32·i/5)` = 6, 12, 19, 25 → snapped to full-attention blocks within two indices (earlier on a tie): 6→**7**, 12→**11**, 19→**19**, 25→**23** (23 and 27 both at distance 2; earlier wins); plus the last block **31**. Deltas at the inputs of layers **[7, 11, 19, 23, 31]**; layer 0 stays the embedding channel. Up to 6 vectors per memory row (input + 5 deltas), payload ≈ 6× the input-only bytes. The 19→23→31 spacing is what the rule gives; it is not tuned.

**Pairing.** Same `SEED` (data order, held sampling, fresh-adapter init). The delta heads are built inside `torch.random.fork_rng(devices=[])` after `torch.manual_seed(torch.initial_seed() ^ 0xDEE9)`, so the shared modules (built before) and the side/reader LoRA (injected after) draw the identical sequence in both arms, and the heads themselves are a function of the seed. The bench's `parameter_hash` now hashes by name and skips `delta_heads.*`: `initial_hash` (shared parameters) must match between NDC and NDI, and `result.json` records `deep_hash` over the heads separately (test: `test_pairing_shared_draws_are_identical`).

**Head size.** Bottleneck `r = max(1, min(d_side, d_target) // 4)` = 640: each head `2560→640→2560` ≈ 3.3 M params, five heads ≈ 16.4 M (vs ≈ 26 M for one 4× `RowHead` at width 2560); fp32 like the other AC modules. Memory: negligible next to K16's 56 GB peak at micro-batch 3 (deltas are M×2560 per layer per example, M ≈ passage_tokens/16). Expect NDI ≤ +5 % wall time (five small head evaluations per encode, five adds per reader forward).

**Calibration.** Before optimizer construction, `calibrate_interventions(sequences, item_ids)` runs the reader (its adapter active, no rows, `torch.no_grad`, one sequence per forward, no padding) on the first 8 examples of the training order, each tokenized as its stripped history (`strip_ac_parts` of the item: the plain passage plus the target, the same sequence the no-context reference reads; `example.teacher_ids` is empty under SFT, so the trainer builds this reference explicitly), records the mean RMS of each resolved layer's input over all positions, and sets `scale_l = 0.01 × rms_l` in fp32. `calibration_rms` (a buffer) and `calibration_items` (the item ids, in the checkpoint dict) are stored; never recomputed on load; a deep model whose scales are uncalibrated refuses to encode (clear error). The encoder is not involved, so NDC is untouched. Deterministic given `SEED` (test: `test_deep_encode_and_calibration`).

**Submission (ORCD, preemptable):** after applying the patch, `snapshot.py` tags the tree and writes a fresh `training_source.json` (`launch.py` verifies every hash before running, so the deep bench copy must ship *that* manifest); rsync the tag's `activation/` and bench to `~/activation_ws_deep` and `~/activation_artifacts/ac_recon_deep` (never `--delete` toward `~/activation_ws`); then `bash orcd_run_deep.sh NDC mit_preemptable rtx_pro_6000 2` and the same for `NDI` (2-h limit each; ND took 31 min including the example build and the reference pass, whose cache `references_material_r16_k32_gold1_n8192.pt` already exists under the shared preparation folder, so the deep runs skip it). H200 is fine when a preemptable H200 is free; the arms are small enough that the GPU type does not matter. The four-GPU preemptable cap is fully used by K16r1/r2 (end ≈ 15:45 UTC), A8K and X40KD, with the N-arms queued behind; to give the POC 1–2 GPUs promptly: `scontrol hold` the *queued* N-arm jobs (never running ones), submit NDC then NDI, `scontrol release` the N-arms once both have started. Both are `--requeue` and resume from their own `SYNC_RUNS/<LABEL>` checkpoint root like every other arm. `NDIg` follows when a slot frees.

**What the report must show** (widgets `interventions` and `intervention_grads`, every 25 updates like `gate_trace`, plus `result.json` fields): per layer the scale value (which *is* the applied delta RMS, rows being unit-RMS), its ratio to the calibration RMS, the head's gradient norm before clipping, the input row scale (already traced), `grad_norm_ac` beside it (joint clipping means the heads' gradients enter the shared parameters' clip factor in NDI), and the payload bytes handed to the reader. `result.json` gains `interventions: {layers, calibrated, calibration_items, calibration_rms, scales, head_parameters}`, `deep_hash`, `payload_bytes`, and the `deltas_off` panel (`deltas_off`, `deltas_off_novel`, `deltas_off_wiki`).

**The `deltas_off` panel (review 1, finding 3).** At ND's grouping the delta scales cannot move more than ≈ 0.05 absolute over the run (Adam moves a scalar by about its rate per update), so their trajectory is expected to be *flat* and carries no usage signal; and the no-context floor strips rows and deltas together. The usage readout is therefore an eval-only panel: at the baseline and at every reporting boundary the reporting items are scored a second time with their rows kept and their payload withheld (`ActivationContextTrainingConfig.deltas_off_panel`, `_evaluate(deltas_off=True)`, one flag on `_assemble_student`). `held − deltas_off` is the deltas' contribution; it costs one extra panel pass and touches no training-path code. The bench turns it on for every arm (`DEFAULT_ARM.deltas_off = True`; input-only models simply produce no such panel).

**Reading the result.** Primary: held novel gold NLL NDI vs NDC at the final panel (ND: 0.712) and along the 8 panels, with `held − deltas_off` as the deltas' contribution at each panel; secondary: wiki, no-context floor (must stay ≈ 1.87: deltas are removed with the parts, so the floor is also the content-removal control), token accuracy, fidelity on the 4 samples, clean-subset numbers via `clean_panel.py`. A deep arm that matches NDC *and* whose `deltas_off` panel equals its held panel says the reader ignored the deltas (then NDIg); a worse floor says the deltas leaked into the reader drift. The scale trajectory is expected flat at ND's grouping and is not a usage signal.

## 4. Non-interference rules

- **Running and queued jobs never see the new code.** Node 1 runs from `/root/sky_workdir_v2` and ORCD from `~/activation_ws` + `~/activation_artifacts/ac_recon_v2`; nothing syncs the working tree automatically. ORCD jobs are `--requeue` and restart from that checkout, so it is **not replaced**: the POC gets `~/activation_ws_deep` + `~/activation_artifacts/ac_recon_deep` (rsync of the new tag's `activation/` and bench), and `orcd_run_deep.sh` (a copy of `orcd_run.sh` with `AC_RECON_SOURCE_ROOT`, the bench path and a distinct `AUTOTUNE` symlink target pointing at the same shared profiles). `orcd_run.sh` itself is not edited.
- **Existing arms are bit-for-bit unchanged.** With `interventions = 0` no head exists, no RNG is drawn, no kwarg is passed to the decoder, no hook is installed (hooks are installed on the first forward that carries a payload, and early-return without one), the `modules` state dict has exactly the keys it had (heads and calibration buffers are registered only when deep; the checkpoint dict gains an `interventions` entry only for deep models), and `load()` treats a missing entry as input-only (a deep checkpoint into an input-only model, or the reverse, is refused: migration is explicit). Gate: `test_batched.py`'s 13 tests pass unchanged; `test_zero_mode_is_the_previous_model` checks the state-dict keys, a strict load of a `modules` checkpoint written by the tag's code, and bit-identical encoder rows and reader hidden states against outputs saved by the tag's code (`activation/tests/data/`).
- **Config default.** The plan settles `intervention_frequency: int = 4`. This POC checkout ships **`intervention_frequency = 0`** (field names and semantics exactly as settled: `intervention_frequency`, `add_last_layer_intervention = True`, `prefer_attention_interventions = True`; the last two are inert at 0). Reasons: every test fixture, every bench arm and every agent-path model construction would otherwise become deep silently, contradicting "old checkpoints/records mean input-only"; and the POC has not yet shown the default is good. The product default flips to 4 in the same change that lands M3/M4, once NDI beats NDC. The bench's `DEFAULT_ARM` carries `interventions=0, last_layer_intervention=True, prefer_attention=True` explicitly so every arm is self-describing.
- **Local application order.** Implement and test in a worktree from the tag (below); apply to `/workspace` only after the reviewer's second pass; tag with `snapshot.py` (new `training_source.json`); rsync that tag's `activation/` + bench to `~/activation_ws_deep` / `~/activation_artifacts/ac_recon_deep` (four path edits in `orcd_run_deep.sh`: `cd`, `PYTHONPATH`, `AC_RECON_SOURCE_ROOT`, the `launch.py` path; `AC_RECON_ROOT` stays shared so `preparation/`, `initial` and the references cache are reused; the AUTOTUNE symlink is already per label); node 1 is not touched (its remaining arms K16D/A4K/X40K/K16G0 finish on their frozen checkout).
- **Never**: read/edit `IB/TASK.md`; sync `.env`; copy the ORCD `~/.bashrc`; `pkill -f` patterns matching our own shell; edit `remote*.sh`/`orcd_run.sh` while an invocation runs.

**Worktree procedure (phase C).** `git worktree add <scratchpad>/deep-wt ac-recon-20260916T132825Z` gives HEAD's tree plus the tagged `activation/` and bench. Tests: `cd <worktree> && HF_HUB_OFFLINE=1 PYTHONPATH=<worktree> /workspace/.venv/bin/python -m pytest activation/tests/test_interventions.py -q -p no:cacheprovider` (self-contained: a tiny 2-layer Qwen3 reader under `activation/tests/data/tiny_qwen3` and a 6-layer hybrid Qwen3.5 text model built on the fly, `full_attention_interval 3` → full blocks 2 and 5, so the real `Qwen3_5DecoderLayer`, the GDN layers' kwargs and the hybrid cache offset are exercised), plus the existing CPU suites copied out of `IB/TMP` (`test_batched.py`, `test_recon.py`, fixtures in `codesign_implementation/`) run with the same `PYTHONPATH`; the venv is `/workspace/.venv` (torch 2.13 CPU-only here, transformers 5.15.1, `fla` stubbed to `None`). Apply to `/workspace` with `git apply --binary poc_changes.patch` (the diff of the worktree against the tag, new files included), then rerun the same tests in `/workspace`.

## 5. Implementation plan (phase C)

**`activation/ac_model/ac_model.py`**
- Config: `intervention_frequency: int = 0`, `add_last_layer_intervention: bool = True`, `prefer_attention_interventions: bool = True`; `__post_init__` validates `>= 0`.
- `resolve_intervention_layers(num_layers, layer_types, n, last, prefer_attention) -> list[int]` (pure function, in `ac_model_utils.py`): the plan's rule; unit-tested on the Qwen3.5 layout (expect `[7, 11, 19, 23, 31]`), a 2-layer all-full model (expect `[1]`), n = 0 (expect `[]`, whatever `last` says), snap ties.
- `ActivationContextModules`: `self.delta_heads = nn.ModuleDict({str(layer): DeltaHead(d_side, d_target, r)})` built from the resolved layers (from the target's `model_description.layer_descriptions`, resolved in `ActivationContextModel.__init__` and passed in); initialised under `fork_rng` + `manual_seed(initial_seed() ^ 0xDEE9)`; buffers `intervention_calibration` (one RMS per layer) and `interventions_calibrated` registered **only when deep** (zero mode keeps the previous state-dict keys); the layer list lives in the checkpoint dict (`interventions.layers`), not in a buffer.
- `_ensure_scales` leaves delta scales alone; `calibrate_interventions(sequences, item_ids)` (reader forward with `capture_layer_input_rms` hooks, sets `scale_l = 0.01·rms_l`, fills the buffers, keeps the item ids); `encode_batch` raises if deep and uncalibrated; `intervention_summary()` for reports and checkpoints.
- `_encode_prepared_batch`: after `target_head(rows)`, `layer_inputs = {layer: head(rows_pre_head)}` for non-recursive rows; results carry `ACOutput(input_embeds, layer_inputs)`. Public `encode_batch(requests, *, with_layers=False)` keeps returning row tensors for every existing caller and returns `ACOutput`s when asked (plan's ACOutput, minimal blast radius; `RowCache` stores the `ACOutput` in rollout mode with byte counts over every tensor; recursive results have an empty map).
- `save`/`load`: state dict already includes the heads/buffers; `config` in the dict carries the three fields; `load()` adds them to the structural comparison with the missing-key default 0 (legacy checkpoints = input-only) and a clear error when the checkpoint's layer list differs from the resolved one.
- `parameters()`/`trainable_parameters()` unchanged (heads are module parameters); `stats` gains `intervention_seconds`.

**`activation/ac_model/ac_model_utils.py`**
- `ACOutput` dataclass; `DeltaHead(d_in, d_out, r)`: `Linear(d_in, r) → SiLU → Linear(r, d_out)`, fp32, `forward = scale · unit_rows(ffn(x))`, `scale` a scalar parameter initialised to 0 (calibration sets it; `numel()==1` puts it in the gate group when one exists).
- `resolve_intervention_layers` (above).

**`activation/harness/hf_utils.py`**
- `class Interventions(TypedDict): positions: list[int]; layer_inputs: dict[int, Tensor]` (positions are indices into the unpadded physical row; every tensor `[M, d_target]`; scales already applied).
- `install_intervention_hooks(model)`: idempotent; locates the text decoder as `decoder.language_model`/`text_model` when present (never a vision tower; `text_decoder()`/`decoder_layers()`), registers one pre-hook with kwargs on the **text model** that binds the forward's `interventions=` list to the cache offset (`past_key_values.get_seq_length()` *before any layer has run*; 0 without a cache) as a `BoundInterventions` travelling in the kwargs, and a pre-hook with kwargs on **every decoder layer** that returns a new kwargs dict without the entry (no `pop`, so no kernel ever sees it) and, when a payload names the layer, adds the delta rows at `positions − offset` **out of place** (`hidden.clone()` then `index_add_` on the clone; an in-place add would hit the previous checkpointed layer's saved output) in the activation dtype; rows outside `[offset, offset + S)` are skipped. Because the payload travels in the layer kwargs, HF's `GradientCheckpointingLayer.__call__` captures it in the checkpointed partial and the recompute re-adds the same tensors — no global "current payload", two pending forwards keep their own payloads, and it composes with `checkpoint_adapter_scope`.
- `generate_with_interventions(peft_model, *, inputs_embeds, interventions, **generate_kwargs)`: asserts greedy single-sequence (`num_beams == 1`, `do_sample False`, batch 1). HF's `_validate_model_kwargs` rejects an `interventions=` kwarg to `generate` (review 1, finding 1), so the payload is bound by wrapping the **base HF model's** `prepare_inputs_for_generation` for the duration of the call (`functools.wraps` keeps the signature HF validates against; restored in `finally`). For the record: PEFT's `base_model_prepare_inputs_for_generation` (the reviewer's first suggestion) is *not* what HF's loop calls for a LoRA model in this version — PEFT sets it on the `LoraModel`, whose `generate` resolves to the HF model's — a probe confirmed the payload never arrived that way, so the wrapper sits on the HF model instance. The hooks' offset logic makes decode steps no-ops. Test: cached generation equals a manual full-prefix greedy recompute at every step (`use_cache=False` is not a no-cache oracle in HF 5.15.1, finding 2), a spy hook sees every delta row applied exactly once at prefill and none at decode, and `generate(interventions=…)` itself raises.

**`activation/harness/loaded_model.py`**
- `decoder_forward(..., interventions: list[Interventions | None] | None = None)`: when given, `len == B` is checked and the list is passed as a kwarg to the decoder after `install_intervention_hooks(model)`; `None` = today's call exactly.

**`activation/ac_model/ac_model_training.py`**
- `_assemble_student(student_embeds, spans, outputs, dtype, deltas_off=False)` helper used by `_example_loss`, `_batch_loss`, `_sample_completions`: writes `input_embeds` over the spans (as today) and builds one `Interventions` payload per example (`positions` = the span runs in order, `layer_inputs` = per-layer concatenation of the parts' deltas) or `None` for input-only models / `deltas_off`. `_padded_forward(target, embeds, lora, payloads)` passes `interventions=payloads` (right padding keeps positions valid). No-context references and the live-penalty base pass get `None`. `_sample_completions` uses `generate_with_interventions` when the payload is not `None` (spans fully inside the prefix only, as today). `_evaluate(..., deltas_off=True)` and the `deltas_off_panel` flag drive the extra panel.
- Calibration call before `persistent_optimizer` when `ac_model.is_deep and not calibrated`, on `_calibration_sequence` of the first 8 training examples (their stripped histories via a reference `build_example`; deterministic, training-only). `learning_rate_gates_scope="delta_scales"` (the deep scales alone in the gate group) for NDIg.
- Stats: `intervention_trace` (every 25 updates: per layer scale, calibration RMS, applied-delta RMS from the last batch, head grad norm), `payload_bytes`; `summarize` exports them; `_save_epoch`/`_save_partial` unchanged (heads ride `modules.state_dict()` and `optimizer.pt`).

**`activation/ac_model/ac_model_reporter.py`**: one line-plot widget `interventions` (scale / calibration per layer) fed from `report_step`; nothing when the trace is empty.

**Bench `IB/ARTIFACTS/AGENT_AC_PRETRAINING/ac_recon/run_recon.py` + `arms.json`**
- `DEFAULT_ARM += interventions=0, last_layer_intervention=True, prefer_attention=True`; `harness(...)` passes them into `ActivationContextModelConfig`; `resume_state` unchanged; `result.json` gains `interventions` (layers, calibration, final scales, head params) and the run summary line names the layers; arms `NDC`, `NDI`.
- Helpers (`IB/TMP/.../ac_recon/`): `orcd_run_deep.sh` (copy with the deep paths), `orcd_push_deep.sh` (rsync the tag's `activation/` + bench to the deep paths), `panels.py`/`table.py` accept the new labels as-is.

**Tests — `activation/tests/test_interventions.py`** (CPU; tiny Qwen3 reader for the padded-batch and zero-mode checks, a tiny hybrid Qwen3.5 text model with 6 layers and full attention at 2 and 5 for everything that touches the layout, the GDN layers or the hybrid cache):
1. `resolve_intervention_layers` cases (Qwen3.5 layout → `[7, 11, 19, 23, 31]`; ties; n = 0; dedup with last).
2. Zero mode: model built with `intervention_frequency=0` has no heads, no hooks, the previous state-dict keys exactly, loads a `modules` checkpoint written by the tag's code strictly, and reproduces the tag's encoder rows and reader hidden states bit for bit (reference tensors under `activation/tests/data/`); a deep checkpoint into an input-only model is refused and vice versa. Plus the pairing test: zero-mode and deep models built after the same `manual_seed` share identical shared parameters and adapters, the next `torch.rand` agrees, and the heads are a function of the seed.
3. Deep encode: `ACOutput` shapes, every layer map key in the resolved list, deltas' RMS == scale after calibration, uncalibrated deep model raises.
4. Gradients: loss through `decoder_forward` with interventions, direct vs `gradient_checkpointing=True`, equal within fp32 tolerance for every head, both scales, the input head and the reader LoRA; two forwards with different payloads pending before one backward.
