**(2) `kv_slots`.** Exactly the row slices at exactly the chosen layers: the K/V forward hooks on `self_attn.k_norm` (output `[B, S, H_kv, D]`, before `.transpose` and `apply_rotary_pos_emb`) and `self_attn.v_proj` replace `result[row, local[keep]]` with `own · keep + contribution` (`hf_utils.py:190–195`), `local = positions − offset` from the bound cache offset, so prefill writes the prompt rows and decode steps (positions < offset) land nothing while the cache holds the written, then rotated, K/V — the generation test checks the first step's logits against the training forward and greedy decoding against a full recompute. Other positions and the residual stream are untouched (tested). Layers must be full-attention (`_resolve_source_layers`, `ac_model.py:392`), and the stash is reset per layer forward as for `kv`. Deltas-off = no payload = the reader's own K/V (`_assemble_student`, `ac_model_training.py:1238`). Init: `down = 0`, `takeover = 0` ⇒ `own · 1.0 + 0` — bit-identical to no intervention and to the input-only model (tested); the shared draws and the slot head's `up` draw are the K/V delta head's (tested). Gradient at init: `∂L/∂down ≠ 0`, `∂L/∂takeover_{k,v} = −⟨g, own⟩ ≠ 0`, `∂L/∂up = 0` (the LoRA B=0 pattern, one-update delay). Collapse: the content path has no learned scale to walk to zero and no `unit_rows`, so the round-3 mechanism (scale gradient ∝ 1 while the head's ∝ scale) does not exist; the takeover is an independent scalar whose only effect is on `own`, bounded by Σ lr — harmful values (> 1 sign flip, ≪ 0 amplification) are unreachable in these runs, and useful ones too (finding 2). Group: the takeovers sit in the encoder group; they also match `gate_parameters` (`numel() == 1`, `ac_model_training.py:539`), so they appear in the gate trace under their names and would join the gate group if `gate_lr` were set — fine, and the ND recipe leaves it unset.

**(3) `cross_attention`.** The pre-hook writes `hidden[row, start:length] += block(...)` with `start = min(visible_from) − offset` (`hf_utils.py:244–259`): nothing before the first row moves (tested), and the mask `absolute[p] ≥ visible_from[j]` lets position p read passage token j only if p is at or after that part's row-run start — causal in document order across parts; within a part every target token reads the whole passage of the part it is reconstructing, which is the stated point of the ceiling. The reader's own attention is untouched: the delta at p is a function of `hidden[p]` and the passage only, so no later reader position leaks into an earlier one. No all-masked query rows can occur (p ≥ start ⇒ at least one part visible), so SDPA cannot produce NaN. Decode: `length = 1`, `absolute = offset ≥ min(visible_from)` ⇒ every generated position gets the delta with the full mask, as in training (tested against a full recompute). Checkpointing: the block runs inside the layer's checkpointed region and is recomputed on the same payload tensors; direct and checkpointed gradients agree and the side adapter receives gradient (tested). Padding: positions beyond a row's valid length also receive a delta — harmless (masked out of the loss, never attended by earlier positions). See finding 5 on what the number means and finding 6 on memory.

**(4) `load()` / refusal / migration.** Target mismatches are refused by the existing `(source, source_layers, target, depth)` check (`ac_model.py:857–863`; `kv_slots` vs `kv` and vs `residual`, `cross_attention` vs `residual` tested), `kv_slots` additionally requires `head_style = "lora"` at config time (`:159`) so the saved `head_style` agrees. Migration of an input-only checkpoint: the missing-key set is exactly `INTERVENTION_MODULE_PREFIXES` plus the two calibration buffers (`:873`) — the slot heads' `up/down/takeover_*/rms_*` or the blocks' `cross_attention.*` — and calibration is left pending, so the warm arms migrate K16r1 epoch 2 into zero heads/blocks and calibrate at the row positions. `_convert_absolute_scales` returns early for the new targets (`:900`). `save()` stores `intervention_summary()` with `target`, `takeover`, `measurement_only`.

**(5) vLLM plainness of `kv_slots`.** Yes, it is plain. The payload is the additive-K/V payload (M rows × 2 × d_kv bf16 per intervened layer, per request) plus two scalars per layer that are model state, not per-request data. The seam is the one already planned for B1 — after the K/V projections, before the attention op that writes the paged cache — and the operation is a gather/scatter on the row indices of the current chunk's `[num_tokens, H_kv·D]` K and V: `k[idx] = keep_k·k[idx] + rot(slot_k)`, `v[idx] = keep_v·v[idx] + slot_v`. Applying it after RoPE is exact because RoPE is linear per position. Chunked prefill works per chunk on the indices that fall in it; decode needs nothing (the cache already holds the written K/V); prefix caching needs the per-block payload hash already planned. Nothing position-at-a-time, nothing in a kernel, no scheduler or block-table change.

## Findings

**1. HIGH (procedural) — The patch does not apply to `/workspace`.** `git apply --check --binary poc_changes_5.patch` from `/workspace` fails on `IB/ARTIFACTS/AGENT_AC_PRETRAINING/ac_recon/arms.json` (hunk at line 1935): `/workspace`'s file already has `A32DLn`, `NDIAWLn`, `NDIAWLSn`, `NKVWLn`, `NDIWLn` appended after `A32L`. Regenerate the hunk against the current file (or append the five arms manually); the other seven hunks apply.

**2. MEDIUM — The takeover cannot reach the replacement regime at the encoder rate.** `KVSlotHead.takeover_{k,v}` (`ac_model_utils.py:670–671`) train in the encoder group at `encoder_lr = 1e-4`; Adam's per-step move on a scalar is ≈ lr, so Σ lr over NKVSW's 1,024 cosine updates bounds |takeover| by ≈ 0.05 (the write-up's own "0.1 per 1,000 updates at most"). NKVSW vs NKVWL then differs by a ≤ 5 % attenuation of the rows' own K/V — not replacement vs addition. Fix options: `scale_parameters()` → `[self.takeover_k, self.takeover_v]` (`:687`) so they train in the `delta_scales` group at 1e-3 (set `A32KVS.delta_scale_lr` to 1e-3; NKVSW/NKVSWS inherit 1e-3); or keep as is and reword the arm notes to what is actually being tested. Either way the widgets are unchanged.

**3. LOW — `A32KVS` inherits `delta_scale_lr: 0.0` and `scale_fraction: 0.2` from `A32DL`.** Inert today (no scale group for slot heads), but if finding 2 is fixed through `scale_parameters()`, `delta_scale_lr: 0.0` freezes the takeovers in that arm. Set it explicitly.

**4. LOW — The keep factor is applied in bf16.** `hf_utils.py:193` computes `own · keep.to(bf16) + contribution` in bf16: `keep = 1 − takeover` rounds to 1.0 for `takeover < 0.0039` and moves in steps of 0.78 % thereafter, while the takeover's gradient is the exact linearisation — the same forward/backward mismatch the round-3 diagnosis described, here benign (the scalar walks in the right direction and cannot collapse anything) but it makes `intervention_takeover` read values that have no forward effect below 0.4 %. Compute `written` in fp32 and cast once: `(output[row, local[keep]].float() * keep + contribution.float()).to(output.dtype)`; bit-identity at init is preserved (`own · 1.0 + 0` is exact in either precision).

**5. INFO — What the ceiling measures.** Every target token reads the side model's final states at *all* passage positions, including the token it must predict, so NXAW/A32XA can in principle drive the reconstruction loss toward zero by lookup; the number is "can the reader use side states at these five depths at all", not a compression result, and it should be read only as the bound the write-up describes (if it does not beat the input-only line, fetching is not the limitation at these depths). The arm notes say "CEILING MEASUREMENT, NOT A CANDIDATE"; keep that phrasing in the ledger.

**6. INFO — Memory and compute of the ceiling.** The block runs per example per layer over `[L' ≈ 1,750, N ≈ 1,700]` with a boolean mask, so SDPA takes the math path in fp32: ≈ 50 MB of scores plus softmax per head-set, ≈ 150–200 MB per (layer, example), all three examples of a micro-batch alive until the layer's forward ends (≈ 0.5 GB), recomputed under checkpointing. Fine on the 96 GB cards; worth knowing if `micro_batch` is raised.

**7. INFO — `visible_from` is a Python list in the payload.** It is rebuilt as a tensor at every intervened layer's pre-hook (`hf_utils.py:250`), five small host→device copies per forward per example; negligible, but a one-off tensor at assembly would remove them.
