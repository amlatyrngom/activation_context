## Findings

### HIGH

**1. The reporter asserts on the first intervention trace of every deep arm (not only A2).** `activation/ac_model/ac_model_reporter.py:165` calls `self.initialize_line_plot("intervention_attention", ...)` *inside* `for layer, value in entry["head_grad_norm"].items():` (line 162) with no `"intervention_attention" not in self.widgets` guard; `HtmlReporter._add_widget` (`activation/common/reporting.py:541`) asserts the name is new. With five intervention layers the second iteration of the very first trace entry (update 25) raises inside `report_step`, which the trainer calls on every update when a reporter is attached — the bench always attaches `RunReporter`. So NDI, NDIL, NKV, NDIg, NDIR, NDID, the warm arms and all six A2 arms die at update 25. The 26 unit tests never attach a reporter, and the bench tests never run a deep arm to 25 updates, which is why 42 tests pass. Fix: move the call into the `if "interventions" not in self.widgets:` block (lines 143–158), or guard it with `if "intervention_attention" not in self.widgets and entry.get("attention_out_norm"):` so non-A2 arms do not get an empty widget. Add a test that drives `ActivationContextTrainingReporter.report_step` with two deep trace entries of two layers each (the probe above is ten lines).

### MEDIUM

**2. A phase-C deep checkpoint's `optimizer.pt` cannot be resumed under the phase-E layout (phase E (a)/(d)).** Input-only runs are unaffected (the `delta_scales` group is appended only when `ac_model.is_deep`, `ac_model_training.py:521–533`, so X40K-style `optimizer.pt` with two groups still loads). But a deep run started on phase-C code saved two groups with the absolute `scale` parameters in group 0; phase E's optimizer has three groups (relative scales last), and `optimizer.load_state_dict` (`ac_model_training.py:542`) raises on the group-count mismatch, while `resume_state` (`run_recon.py:244–262`) insists on `optimizer.pt` and the bench sets `resume_optimizer=True` whenever a completed epoch exists under the arm's root (`run_recon.py:328`). Any phase-C deep arm that is requeued or continued after the rsync crashes at optimizer build rather than falling back. Fix (either): before pushing, confirm no phase-C deep root (NDI/NDIg run on the tag) is left under `ACTIVATION_SYNC_ROOT` on the node — or move such roots aside as `resume_state` already tells the operator to for the missing-file case; or make the load tolerant: when the group counts differ and the checkpoint's `interventions.parametrization` is absent, drop the moments and log "optimizer state discarded (layout changed)". Warm starts are not affected: `init_ac`/`init_reader` load adapters only (`run_recon.py:289–290`) and never `optimizer.pt`.

### LOW

**3. `attention_grad_norm` is read after clipping while `head_grad_norm` is read before it.** `ac_model_training.py:644` captures the head norms before `clip_grad_norm_`, but the trace entry is built at line 660, after clipping, and `_intervention_trace_entry` reads the block gradients live at line 1237. The two columns of the same trace entry are therefore on different footings (review 2 finding 2 was about exactly this for the heads). Fix: return the block norms from `_head_grad_norms` alongside the head norms (dict keyed `"attn:<layer>"`), or take a second pre-clip snapshot at line 644.

**4. "final" depth copies the passage states to fp32 once per intervention layer.** `ac_model.py:646` evaluates `hidden[row, :end - num_rows].float()` inside the per-layer loop, so five identical fp32 copies of the [N, d] passage state are made per example, each retained for backward by that block's LayerNorm: at N ≈ 1700, d = 2560 that is ≈ 17 MB × 4 redundant copies × micro-batch 3 ≈ 200 MB per side forward, plus the same again for the normed copies. Hoist the `.float()` above the `for index, layer` loop (one copy per example). At "matched" the per-layer captures are different tensors, so only the intrinsic cost applies (≈ 260 MB of fp32 views' copies per side forward of three examples at 1700 tokens; acceptable on 80 GB, but worth knowing when `micro_batch` is raised). Under side checkpointing the whole-sequence capture itself (`hf_utils.py:297–311`) is a view of the layer input that the non-reentrant checkpoint holds anyway, so it adds no memory — confirmed by the checkpointed gradient equality in the `passage_matched_kv` case.

**5. Per-forward host syncs in the hot path (phase E).** `hf_utils.py:207` (`float(...)` of the row RMS in every intervened layer's pre-hook, on every forward including eval, `deltas_off` panels and each decode step's prefill) and `ac_model.py:658` (`float(cosine)` per row per layer per encode) are GPU→host syncs: 5 per reader forward and 5 per encoded row. Cheap in absolute terms (~50 µs each) but they serialise the launch queue; accumulate the values as 0-d tensors and convert once per trace point (every 25 updates) instead. Related: `intervention_diagnostics["cosine"]` is drained only by the training trace, so in rollout/eval-only use of a deep model it grows without bound — clear it in `set_mode` or cap the per-layer list.

**6. `NKV` note says "1% of the reader's K and V RMS"; the default `scale_fraction` is 0.05** (`arms.json:894`, `run_recon.py:34` `scale_fraction=0.05`). Cosmetic, but it will mislead the reading of the first trace. Fix the note to "5%".

**7. `intervention_attention_depth` is accepted and silently ignored for non-attention sources.** `ac_model.py:138` only validates the value; `intervention_attention_depth="matched"` with `intervention_source="summary"` builds a summary model, and `load()` masks the field to `None` for such configs so nothing later notices. Harmless for the bench (the arm files never set it without `passage_attention`), but a `ValueError("intervention_attention_depth applies to intervention_source 'passage_attention' only")` for a non-default value would match the `intervention_source_layers` rule two lines below.
