## What changed

### 1. `intervention_head_style = "lora"` — `activation/ac_model/ac_model_utils.py:516-594`

`DeltaHead` (`:519`) and `KVDeltaHead` (`:557`) take `style`. In `"lora"` the forward is `down(silu(up(z)))` (`:548`, `:588`) — no `unit_rows`, no `rms × relative` factor — and `down.weight`/`down.bias` are zeroed after the seeded draws (`:539`, `:577`), so the delta is exactly 0 at init and the head owns its magnitude (the radial degree of freedom `unit_rows` annihilated is back; the gradient at delta = 0 is the exact linearisation, no bf16 error there). The `relative` parameter(s) and `rms` buffer(s) **stay registered** (same state-dict keys as the scaled style; no migration) but are inert: `relative` is created with `requires_grad=False`, `scale_parameters()` returns `[]` (`:552`, `:593`) so the optimizer never builds a scale group, and `ActivationContextModel.trainable_parameters()` filters on `requires_grad` (`ac_model.py:494`) so the inert scalars never reach the encoder group either. `PassageAttention` is untouched (its `out` was already zero-initialised).

- Config and validation: `ac_model.py:127-131`, `:151-156` (`heads_frozen` + lora is refused: a lora head with frozen weights emits nothing). Heads built with the style: `:222`, `:225`. `intervention_summary()` reports `head_style`, `calibration`, and `parametrization = "lora"` (`:406-407`). `load()` refuses a checkpoint whose `(head_style, calibration)` differ from the configured pair (`:798-801`; checkpoints written before this round read as `("scaled", "no_rows")`, so nothing old is refused).
- Bench: `harness(..., head_style, calibration)` → `intervention_head_style` / `intervention_calibration` (`run_recon.py:81`, `:108`); the run summary describes the style and the calibration (`:326-328`).

### 2. `intervention_calibration = "row_positions"` — `ac_model.py:413-488`, `ac_model_training.py:1253-1262`, `hf_utils.py:247-297`

`calibrate_interventions(sequences, item_ids, *, row_inputs=None)` (`ac_model.py:424`): in `"no_rows"` it is exactly the old measurement (median residual RMS over the stripped histories' positions, first token excluded; K/V: mean K and V RMS); in `"row_positions"` it takes `row_inputs` — per sequence the reader's input embeddings **with the encoded rows written over the placeholders** (no deltas) and the row positions — and records the mean over those positions of the per-position residual RMS (K/V: the K after `k_norm` and the V after `v_proj` at those positions), i.e. the same quantity the intervention hooks write as `row_rms` on every training forward. The mode and the inputs must agree (`:438-442`), so `intervention_summary()["calibration"]` is trustworthy. The trainer builds the inputs with `_calibration_rows` (`ac_model_training.py:1253`): `encode_batch` under `no_grad` inside `ac_model.uncalibrated_encoding()` (`ac_model.py:413`; the only way a deep model encodes before calibration; the diagnostics it records are discarded), then `_assemble_student(..., deltas_off=True)`. The captures gained an optional `positions` argument (`hf_utils.py:247`, `:277`). In the lora style the value feeds the diagnostics only (the forward never reads `rms`); in the scaled style it is the head's anchor as before, now 3× closer to the truth at layer 7.

### 3. `intervention_delta_rms` — `ac_model.py:706-735`, `ac_model_training.py:1277-1321`, `hf_utils.py:167-170`, `ac_model_reporter.py:155-158`, `:175`

Every training-mode encode records the applied delta's RMS per layer (`_record_diagnostic("delta_rms", …)`, `ac_model.py:708-716`; K/V per half under `"l:k"` / `"l:v"`; 0-d tensors, no host sync, capped at 256 per key like the cosine). The K/V hooks now also write `row_kv_rms` (K and V RMS at the row positions) next to the residual `row_rms` (`hf_utils.py:167-170`); `_harvest_row_rms` collects both (`ac_model_training.py:1312-1321`). The trace entry gains `delta_rms` = applied RMS / row-position RMS of the same forwards (residual: against `row_rms`; K/V: each half against its own K or V row RMS) and `delta_rms_abs` (`:1286`, `:1304-1309`); the widget `intervention_delta_rms` plots the ratio (`ac_model_reporter.py:155`). The cadence of the intervention trace is now every 5 updates below 200, every 25 after (`_intervention_trace_due`, `ac_model_training.py:1265`; used at `:689`); the gate trace keeps its 25. The `interventions` and `intervention_grads` widget texts say how to read them per style.

### 4. `intervention_heads_only_updates` — `ac_model_training.py:109`, `:150`, `:529-533`, `:665-672`, `:684`, `:1143`

Mirrors `target_lora_frozen_updates`: before the loop the intervention parameter ids (`delta_heads.*`, `passage_attention.*`) are collected and `staged_parameters` = the encoder group minus those (`:531-533`; raises for an input-only model, `:529`). While `updates_done < N`: the reader counts as frozen (`:666`, its group rate zeroed at `:684`, no penalty term via `_penalty_active`, `:1143`), and every staged parameter's `.grad` is set to `None` after the backward (`:670-672`) so it neither steps (AdamW skips it; its moments stay fresh until release) nor enters the clipping norm; only the heads and blocks step. `set_learning_rates` runs every update as before, so the warm-up and the cosine keep their clock through the staging; a resume restores `updates_done` from `optimizer.pt`, so the staging continues where the checkpoint left it (no group-layout change, moments resume). Bench key `heads_only_updates` → `intervention_heads_only_updates` (`run_recon.py:199`).

## Deviations / decisions

1. **The inert scales stay in the state dict** in the lora style (`relative*`, `rms*`): no new keys, no migration, one checkpoint layout per head shape; they are made inert by `requires_grad=False` + an empty `scale_parameters()` rather than removed. `intervention_summary()["scales"]` still reports `rms × relative` for them (an anchor, not an applied magnitude); `parametrization` says `"lora"`.
2. **Calibration mode lives on the model config** (not the trainer) so the checkpoint carries it and `load()` can refuse a mismatch; the trainer only decides which inputs to build. A checkpoint calibrated one way never loads under the other mode (the scaled forward would silently change meaning).
3. **The K/V denominator is measured live**: rather than dividing the K/V delta RMS by the static calibration, the K/V hooks write `row_kv_rms` so the ratio uses the same forwards as the residual case. The residual `row_rms` at K/V layers is still traced as before.
4. **Trace cadence**: only the intervention trace moved to 5/25; the gate trace stays at 25 (its readers and the existing arms' reports are unchanged).
5. **Heads-only staging drops gradients rather than toggling `requires_grad`**: the backward still runs through the encoder (no compute saving), which keeps the checkpointing paths, the `encoder_has_grad` cache invalidation and the resume layout exactly as in the reader recipe; a cheaper variant (detach the source during the staging) is one line if the 200 staged updates prove worth their cost.
6. **`heads_frozen` + lora is refused** (nothing would train in the head); the NDIR-style control for the lora style is `detach_source`, unchanged.
7. Not done: no GPU run, no vLLM change (the payload shape is unchanged: per-row deltas at positions, nothing position-at-a-time), no change to `learning_rate_delta_scales`'s default (the lora style simply has no group; scaled arms keep their group and rate).
