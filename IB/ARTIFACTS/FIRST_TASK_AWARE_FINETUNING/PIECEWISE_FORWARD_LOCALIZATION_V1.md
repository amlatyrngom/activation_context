# Forward localization of the failed encoder-budget proof

Prepared and CPU-checked; not staged or submitted. Use `bench/probe_piecewise_forward_localization_v1.sbatch` for one RTX PRO allocation capped at15 minutes, eight CPU cores and64 GiB host memory. It writes `reports/piecewise_forward_localization_v1/proof.json` and uses its own private workspace. Existing runs and failed proof receipts remain unchanged.

The worker imports the pinned strong-parent loader, retaining all completed32k paired-checkpoint, source, material, Adam and input guards. It selects exactly the second sorted two-question microbatch from the recorded failing case:24 passages with original side-encoder shape `[24,2507,2048]`. The only variants are65536, unchanged65536 repeat, and32768. The side-encoder forward retains gradients, training mode with dropout disabled, checkpoint threshold zero and original masks. There is no reader forward, backward, optimizer update or checkpoint save. No CPU activation offload or precision override is used.

The shortest and longest original requests are fixed by token count, ties by request index. Their valid activations are captured before/after the mixer, entering the side encoder, after each side layer/final normalization, and in final input rows/deep deltas. Request token hashes, original indexing, content/row lengths, caller mask validity and text positions are checked. Actual internal mask/position hashes and any representation changes are retained. A missing mask versus a materialized one is not silently declared identical; such differences are observations for the investigation. The CPU example exercises this distinction when smaller batches become singletons.

The receipt reports the first nonzero difference and first failure of the original RMS criteria per selected passage. It also stores each captured tensor's size, baseline/candidate squared norms and dot product, permitting direction and magnitude analysis at that stage. Activations are compared in memory; large tensor dumps are not copied to reports. Dependency versions and the actual side-layer implementation hash are recorded. This is diagnostic instrumentation, not a speed benchmark.

The unchanged repeat must be bitwise exact. Caller mask, position, request or parameter-state violations fail. Hook removal and restored method wrappers are checked. The diagnostic exits the reused loader through a private sentinel after this one case, then explicitly repeats parent weight/optimizer hashes. Completion is `diagnostic_complete` with `equivalence_validated=false`, never a strict equivalence pass; quantiles do not run.

Focused checks passed with real tiny hybrid models and the frozen AC/trainer/utils snapshot: changed batching, correct request mapping,28 captured stages per variant, exact repeat, valid input masks/positions and removal of every diagnostic hook. Receipt fixtures verify the early-stop path rehashes unchanged parent payloads, rejects changed payloads and restores the original proof callback on both success and error. The harness may install its own input-gradient hooks when enabling checkpointing; the cleanup check targets the diagnostic's exact hook IDs and method attributes. Python/shell syntax checks passed. Receipts and exact hashes are in `PIECEWISE_FORWARD_LOCALIZATION_PREPARATION_V1.json`.
