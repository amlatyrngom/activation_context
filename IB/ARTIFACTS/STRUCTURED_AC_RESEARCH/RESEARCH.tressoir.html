Agentic programs without text generation

Use an AC backbone as a callable neural function: read text or activations, compute in latent slots, return typed values and optional latent state. Let the program compose these calls and set the final answer directly.

  • Proposal, not an implementation plan
  • No experiments launched
  • Grounded in the current checkout and primary literature

The direction I would pursue

Build a small family of structured neural nodes, then ask whether an entire useful workflow can run through those nodes. The strongest paper story is the joint design of the node’s computation, its communication format, and the program that schedules it. A classification head alone is a useful baseline; the research question is what changes when that interface extends across the whole program.

I would start with evidence aggregation over documents, follow with semantic operand selection plus exact numerical execution, and use a bounded action policy as the more ambitious demonstration. In every case, all model calls can have structured outputs, and ordinary code can call set_final_answer().

A useful working thesis: for tasks whose solutions admit a compact executable structure, a harness can expose that structure at the model boundary, replacing repeated language serialization with learned computation and explicit dataflow. Whether this improves quality, latency, or training efficiency remains an empirical question.

The useful boundary is a bounded decision structure

The output need not come from a small global vocabulary. It needs a tractable representation for each request. A pointer can return a previously unseen name. A numerical head can return a real value. A short sequence of operator choices can compute an answer whose decimal rendering has never appeared in training.

Output contractHow the head returns itWhere the boundary lies

Small answers can require difficult reasoning. A yes/no entailment judgment may depend on an exception two pages away. A single number may require identifying the right population, time period, denominator, and unit. Regexes can locate candidate phrases or numbers; they do not generally resolve these semantic relationships across paraphrases and documents.

Use deterministic parsing wherever it is sufficient. The interesting learned work begins at disambiguation, relevance, coreference, scope, semantic matching, and evidence combination. “Cannot be solved by regex” is a motivation, not a sufficient baseline: a small trained encoder, a cross-encoder ranker, and symbolic execution can also be strong competitors.

1 · Evidence reasoning: expose a decision, preserve unresolved information

A leaf reads a claim and a passage. It returns evidence scores and a compact latent message; a parent reads the messages and produces the document-level result. The informative question is whether the latent channel retains distinctions that a leaf’s local verdict would discard.

Illustrative case: one section says information may be shared with advisers; another limits this to advisers under a confidentiality obligation. The claim concerns unrestricted sharing. A local “supports” label loses the qualification. The parent needs either a sufficiently rich typed record or latent state that preserves it. This is a concrete test of the communication interface.

ContractNLI already pairs document-level entailment labels with evidence spans and discusses difficulty from exceptions. SciFact supplies scientific claims, abstract evidence, and rationale annotations. Use these as task anchors; a new cross-document conflict benchmark would be a separate contribution, not a property to assume of either dataset.

Decisive comparison: identical trees exchanging (a) verdict probabilities and evidence IDs, (b) a richer fixed semantic record, (c) latent rows, or (d) both. If typed records suffice, keep the simpler interface and frame the result accordingly.

2 · Numerical reasoning: learn the semantics, execute the arithmetic

For “What was the percentage change in operating income?”, regexes can extract all numbers but cannot reliably identify the correct years, metric, adjustments, and direction. Nodes select the old and new quantities, identify the operation, and return source references. A deterministic executor computes 100 * (new - old) / old and formats the result.

FinQA is attractive because it includes financial questions and annotated reasoning programs. DROP provides a broader discrete-reasoning task anchor. A restricted operator / answer-type slice must report its coverage separately from full-benchmark scores.

Research question: can the program learn an accurate expression through structured neural calls without a generated scratchpad? Start with a fixed small expression tree, then allow a bounded loop emitting (op, arg1, arg2, stop). The latter still has sequential decisions; avoiding text generation does not mean eliminating sequential computation.

Direct scalar regression is a useful ablation, especially for approximate estimates, but a poor default for exact arithmetic, dates, large integers, or values far outside the training range. Track unit mistakes, operand mistakes, and execution mistakes separately.

3 · Semantic joins: a less glamorous, potentially stronger efficiency result

Match differently worded records, detect duplicate issues, connect a requirement to supporting evidence, or choose which product description satisfies a specification. The output is a relation or row ID; the hard part is semantic correspondence. A graph can first screen pairs, then resolve ambiguous groups, then enforce global constraints such as one-to-one matching.

Use candidate blocking and exact matching as baselines and preprocessing. Account for the quadratic pair space if blocking fails. Reusable document encodings could make this direction more efficient across many queries, but query-conditioned encodings lose that reuse. Measure both regimes.

4–6 · Extensions, with the task boundaries made explicit

Multi-hop QA: HotpotQA provides multi-document questions and supporting facts. Copying an answer from a selected span gives text output without text generation. Answer aliases, non-extractive answers, and retrieval misses still count; do not silently insert the gold answer into a candidate list.

Action policies: read an observation, select one of a finite set of actions and a current entity ID, execute it, and repeat. Good starting environments expose structured search filters, menu choices, records, or navigation targets. Arbitrary shell commands, unrestricted search-query writing, and open code synthesis exceed the initial interface unless additional bounded representations are supplied.

Verification: rank a fixed set of patches against a bug report or candidate answers against evidence. Tests can establish executable facts while the model judges semantic fit. This supports a complete structured program only when candidate construction is deterministic, externally supplied as part of the task, or itself produced by structured nodes; otherwise claim a verifier component and count generator cost.

Make the entire agentic program structured

Three interfaces are enough to describe the initial system: observations in (text, structured values, or aligned activations), typed values out (for program decisions), and latent memory out (for the next model). The program owns batching, branching, aggregation, tools, and final rendering.

Program A · evidence tree. Split a document by ordinary code; batch leaf calls; merge their outputs; choose a verdict and evidence IDs; map the verdict to its canonical string and submit it. If a tree must retain exact evidence text, keep a source table and pass references alongside memory.

Program B · numerical dataflow. Parse quantity candidates; use structured nodes to identify relevant operands and operations; execute a bounded expression; submit the resulting number. Intermediate results can be numerical inputs to later nodes, with explicit units and role tags.

Program C · observation/action loop. A node returns action type, current target ID, bounded arguments, and a stop score. The program runs the tool and feeds the next observation back. Stop means either submit an available typed answer or a predefined unresolved result. The loop has a step budget and a repeated-state rule. No language-generation fallback is needed for the research condition.

The all-structured condition should instrument zero calls to text-generation APIs at evaluation, including planners, leaf workers, summarizers, query writers, and final-answer formatters. Training-time teachers may generate labels, but their cost and role should be disclosed. Deterministic formatting is allowed; it must not contain task-solving rules that make the neural work disappear.

A fixed evidence tree is a neural dataflow program; the observation/action loop is a stronger agentic example. Keeping these labels precise makes the architectural argument easier to defend.

What markers buy—and what they do not

For a decoder-style backbone, append learned embeddings after the full input:

[text / typed inputs / incoming AC rows]
[scratch_1 ... scratch_S]
[memory_1 ... memory_M]
[verdict] [evidence] [value] ...
             ↓ one backbone forward
       named hidden states → typed heads / outgoing memory

“Encode-only” means no autoregressive token-generation loop. The backbone may still be a causal decoder internally; the repository already calls this operation decoder_forward(). A bidirectional encoder is another possible backbone, but changing masks and pretraining assumptions is a separate experiment.

Slot rolePurposeUseful control
Output slotA task-specific query/readout location for a head.Last-token or pooled hidden state with the same head.
Scratch slotExtra representational workspace before readout.Zero scratch slots; matched extra positions; different slot budgets.
Memory slotExport a compact state that another node can consume.Typed values only; typed values plus selected source snippets.

In a standard causal Transformer layer, later positions attend earlier positions’ states from the preceding layer. Appending 16 scratch slots does not create 16 complete recurrent reasoning steps. It adds positions and changes the available computation within the fixed layer stack. Hybrid backbones can have different within-layer recurrence; neither case makes slot count equivalent to repeated whole-model forwards.

For extra sequential computation, explicitly feed a node’s state into another forward pass, use a tree with more levels, or investigate a recurrent backbone. Keep slot count, graph depth, and number of forward passes as separate experimental axes. Pause-token training, continuous-state recurrence, and recurrent depth are related but distinct mechanisms; see the prior-work map.

Output slots under causal attention are ordered: earlier ones cannot use later ones. Start with the existing causal mask and a documented ordering. For permutation-invariant sets, use appropriate pooling or a set head and test permutations. Several independent logits can produce an inconsistent record; validity constraints, a joint head, or an additional pass are needed when fields depend strongly on one another.

Named slots make readout locations legible; they do not make their hidden computations interpretable. Test whether scratch and memory are used through ablations, edge shuffling, and task-preserving counterfactuals. A confidence head also needs calibration; its name is not evidence of reliability.

A minimal structured_ac_model.py

Yes to a sibling model with a small typed contract. Reuse the AC encoding machinery, but avoid inheriting the requirement that every model must emit activations for a generative reader. Generic PyTorch modules are useful at the input-adapter and output-head boundaries; they still need explicit shape, masking, representation-space, and serialization contracts.

The smallest surface worth designing

# Proposal only: these names are not implemented.
@dataclass
class StructuredRequest:
    messages: list[dict]                 # existing text/message dialect
    values: dict[str, Tensor]            # optional typed numerical inputs
    memories: list[LatentValue]          # rows + mask + space/producer version
    candidates: dict[str, CandidateSet]  # request-local IDs, masks, features

@dataclass
class StructuredOutput:
    tensors: dict[str, Tensor]           # logits, estimates, pointer scores
    memory: LatentValue | None          # live tensor graph during training

class StructuredACModel:
    def forward(self, batch) -> list[StructuredOutput]: ...
    def predict(self, batch) -> list[StructuredOutput]: ...

# Configuration declares slot groups and their readouts.
slots = {"scratch": 8, "memory": 8, "verdict": 1, "evidence": 1}
heads = nn.ModuleDict({
    "verdict": nn.Linear(d_model, 3),
    "evidence": CandidateScorer(d_model),
})
# Each named head receives its slot states plus requested candidate/content
# features and masks. Fixed heads may use only their slot states.
# The program, not forward(), maps predictions to Python values / text.

forward() must preserve gradients and avoid detached rollout caches. predict() provides inference-mode execution, batching, and optional versioned caching. Losses stay outside the model: cross-entropy for labels and pointers, appropriate numerical loss for regression, and auxiliary supervision only where labels exist. Raw tensors should remain available until the caller chooses argmax or a constrained interpretation.

For saved configurations, store a module factory or importable class specification, JSON-compatible kwargs, schema/version information, and a state dictionary. An arbitrary live nn.Module is convenient in a notebook but is not a complete portable checkpoint format. Defer a large plug-in system and universal schema language.

Make latent edges explicit

A LatentValue needs rows and a validity mask, an identified representation space, and producer/checkpoint provenance. A consumer maps it into its backbone’s input space with a trained adapter and role/position treatment. Equal width is not semantic compatibility, even for two adapters over the same base model.

Start with a shared backbone and a shared trained communication space. To accept an existing AC model’s output, use one of two explicit paths: (a) consume the complete ACOutput in the exact reader architecture it targets, including supported deep interventions; or (b) train an adapter that defines which channels it consumes. An embeddings-only adapter is an ablation, not transparent preservation of a deep AC message. Existing layer-indexed residuals are not portable to arbitrary backbones.

Keep opaque memory separate from exact provenance: document IDs, offsets, candidate tables, masks, and units travel as ordinary typed data. Do not expose every source-token hidden state by default; pointer heads can opt into the token or candidate features they need.

# Pseudocode: get_structured_model / structured_call are proposed.
class EvidenceProgram(AgenticProgram):
    requires_generation = False

    def execute(self):
        task = read_task(self.agent.agent_config)
        source_table, requests = prepare_passages(task)
        leaf = self.agent.harness.module_manager.get_structured_model("leaf")
        root = self.agent.harness.module_manager.get_structured_model("root")

        leaves = structured_call(self.agent, leaf, requests)
        request = make_reducer_request(task, leaves, source_table)
        result = structured_call(self.agent, root, [request])[0]

        verdict = LABELS[result.tensors["verdict"].argmax().item()]
        self.agent.set_final_answer(verdict)
        return self.agent.run_results

# A separate training execution uses forward(), retains tensors on-device,
# and backpropagates across the fixed graph before making hard decisions.

A model call record should contain node ID, parent IDs, model/checkpoint/schema identity, replayable inputs or references, typed outputs, selected actions, and timing. Capture exact latent payloads when needed for replay. Existing assistant-token trajectories do not automatically contain supervision for these calls, and a final answer alone cannot reconstruct them.

Keep this record small for the initial fixed graph. Introduce a structured trace alongside existing run results when integration is needed, rather than manufacturing assistant tokens. The current token-oriented training path cannot be assumed to train such traces.

Training: start with a fixed graph and honest gradients

First train heads and small input/output adapters over a frozen backbone; then compare adding LoRA to the backbone. Compare fresh initialization with the existing AC encoder as a warm start. The current reconstruction / QA checkpoint may provide useful features, but it was optimized for a reader’s task and representation; transfer to direct structured decisions is a hypothesis.

For a fixed tree, leave latent edges as live tensors and backpropagate the root’s task loss through the whole graph. Add evidence or operand losses when ground truth exists. A label-only leaf bottleneck may be too narrow; latent state can be trained to carry information needed by the root without inventing local labels that the task does not provide.

Hard argmax, retrieval, tool execution, and discrete routing interrupt ordinary backpropagation. Initially supervise those choices or keep routing fixed. Later compare policy learning or explicitly chosen estimators. A soft training mixture followed by hard inference needs a measured train–inference gap. External tools are not differentiable merely because their inputs came from a neural head.

Rollout caches and saved traces are detached. They support replay or training a downstream head with a frozen producer, not automatic end-to-end training of the producer. Changing producer weights invalidates cached latents; checkpoint the shared communication contract with the participating adapters and heads. For large graphs, recomputation or staged training is a memory/quality tradeoff to measure.

Use fresh, source-grouped evaluation material. The existing synthesized QA bank may help with shared tasks, but answer strings alone do not guarantee span, evidence, or program supervision. Do not consume the running campaign’s reserved confirmation split as a development set for this new direction.

Experiments that would decide whether this is worth a paper

First result to seek: an all-structured document-evidence program that matches a well-tuned text program’s task quality while reducing end-to-end cost, and whose latent edges improve over an otherwise identical typed-only graph. If the second part fails, a simpler efficiency result may still be worthwhile.

Minimum serious baselines: deterministic parsing/rules where applicable; a smaller discriminative encoder or cross-encoder; a last-token/pooled head on the same backbone; a monolithic structured model; a concise text program; and a graph with typed-only edges. For numerical tasks include symbolic execution with learned operand selection. Avoid choosing only verbose chain-of-thought agents as efficiency opponents.

For the first task, fix retrieval/candidate pools and make all systems see the same evidence. Then run an end-to-end version that charges retrieval and candidate construction. Report candidate recall and schema coverage; for a single-answer selection task, final accuracy cannot exceed the probability that a valid answer is in the pool.

Measure final task quality, evidence/operand correctness, p50 and p95 latency, throughput at stated concurrency, peak memory, GPU-seconds per example, total backbone tokens processed, node calls, bytes transferred, and training/teacher cost. Include multiple seeds or uncertainty estimates. Compare at matched quality and at matched cost; a speedup accompanied by an unreported accuracy loss is not the desired result.

Useful falsifiers: shuffled memory performs equally well; richer typed records remove the latent advantage; a small encoder meets the target much more cheaply; a monolithic head matches the graph; or the improvement vanishes against a one-token baseline. These outcomes narrow the claim and point to which complexity can be removed.

My suggested progression is one evidence task with the essential controls, then a numerical task to establish a different output type, then the action loop if the interface and training already work. This is a research ordering, not an instruction to launch runs.

Where the efficiency could actually come from

Removing autoregressive output can save repeated backbone steps, vocabulary projections, generation KV-cache capacity, and serialization/parsing work. A graph can also avoid making the next node re-read a long textual message. It still pays for input processing, scratch slots, heads, adapters, batching, communication, and every sequential graph level.

For a one-token label, the initial prompt pass already produces the first-token logits. There may be no subsequent backbone decoding step to remove. A custom head saves the large vocabulary projection and changes the learning problem, but extra markers can cost more than that saving. This is why multi-field outputs and repeated intermediate messages are more promising efficiency targets.

\[T_{\mathrm{text}}\approx P+\max(K-1,0)D,\qquad T_{\mathrm{structured}}\approx P+S+H.\]

Here P is measured prompt-pass latency, K is total generated tokens including any required syntax, D is average latency of each subsequent decoding step, S is extra slot-processing time, and H is net head/adapter overhead relative to the text baseline. H can be negative when saved vocabulary-head work dominates. This simplified comparison assumes the same input and excludes graph scheduling and transfer.

Explore the per-node break-even point

At the illustrative defaults: text 584 ms; structured 90.2 ms; ratio 6.47×. With a one-token label, text is 80 ms and structured is 90.2 ms: the structured node is slower.

For a graph, total GPU work sums over nodes; wall time follows the scheduled critical path and actual hardware contention. Parallel leaves on one GPU are not free parallelism. Compare batching, prompt-prefix caching, and cold/warm document caching fairly. Separate query-independent document encoding, whose cost can be amortized, from query-conditioned encoding, whose cache key must include the query.

Latent communication is not automatically smaller in bytes. An illustrative 16 × 2,560 BF16 tensor is 81,920 bytes (80 KiB), before metadata; a short textual message can be much smaller. Fewer backbone positions or less generation work can still win. Report bytes and device transfers as well as token counts. Start with nodes on the same device; cross-machine transfer is another cost regime.

Prior work sets the bar

This is a focused literature check, not an exhaustive novelty search. The defensible opportunity is in the combination and measured behavior of trained AC communication, typed outputs, explicit program structure, and the removal of final language generation.

A candidate framing under Harness/model co-design at the architectural level: “Programs of structured neural calls for bounded-output reasoning.” The paper could ask which information should remain latent, which should become a typed value, and which computation should be executed by the harness.

The most interesting eventual result would be a task-dependent frontier: some workflows need only typed records; others benefit from latent edges; some need recurrent computation; and open-ended synthesis still benefits from language generation. A clear map of those boundaries could be more useful than a universal replacement claim.

My current bets

  1. Highest confidence: compact typed heads are useful when a program already knows the output schema and calls models repeatedly.
  2. Most important uncertainty: whether latent messages add enough over rich typed records and evidence pointers to justify their training and transfer costs.
  3. Best architectural experiment: one fixed evidence graph, all neural nodes structured, with text/typed/latent edge ablations and direct finalization.
  4. Best second task: numerical reasoning with learned operand selection and exact execution, followed by a bounded action loop if the first results warrant it.
  5. Minimal interface choice: a sibling StructuredACModel, a shared feature-forward seam, explicit head/adapter contracts, and a program capability that avoids loading the generation engine.
