edited\begin{abstract} Agent harnesses communicate with models via text or audiovisual token channels. Current harness/model co-design, largely an extension of post-training, leaves this channel fixed, forcing the harness harness to flatten all values into native tokens and truncate information at critical points: long trajectories are compacted into summaries, subagents return only their final answers, and retrieval shows only a few candidates. We propose an alternative form of co-design at the architectural level. The harness declares specialized sub-models that turn arbitrary information into Activation Context: latent values written into the model as input-layer embeddings, hidden-layer residuals or directly ingested key-value (KV) pairs. Previously elided or summarized information can then be efficiently made visible to the model without overflowing its context window. We evaluate Activation Context on four workloads to showcase its general ability to accurately preserve information with with fewer tokens. In retrieval question answering, it matches or exceeds text accuracy with 9-19$\times$9--19$\times$ fewer tokens. In corpus compression on LongHealth, it reaches 81.5\% accuracy using 10$\times$ fewer tokens than the full text corpus, which has an accuracy of 79.5\%. At the same size, Cartridges only reaches 69\% despite using $\sim$100$\times$ more training tokens. When resuming compacted agent trajectories, it preserves nearly as much information as the full context on the hardest tasks while compacting 5.7$\times$5.5$\times$ faster than text summarization. In multi-agent synthesis, it lets an agent read its subagents' trajectories, solving 85.7\% of the most difficult DeepMath-103K problems versus 82.4\% when synthesizing from final results only. \end{abstract}

In our view, the harness/model interface should be enriched to allow the harness to declare arbitrary data types, map them to specific sub-models and determine how they plug into the main model as latent values. We call these latent values Activation Context (AC), and the sub-models that produce them AC encoders. A harness places ACs in its trajectory the same way it places images today, and chooses one of three write modes (\cref{fig:overview}b): Input Embeddings replace token embeddings, Hidden Residuals additionally write to the hidden states of selected layers, and All-Layer KVs are ingested directly into every layer's KV cache. An AC encoder can compute ACs online, as for a compacted trajectory or retrieved documents. ACs can also be trained offline in advance without an encoder (encoder-free ACs) and plugged in on demand, as for a document reused across queries (\cref{fig:overview}a). To keep the KV cache correct, writes only apply to the ongoing turn and are subsequently cached. The interface is inspired by the completions API and is compatible with existing harnesses. We support Input Embeddings through vLLM \cite{kwon2023efficientmemorymanagementlarge} and the other two modes through a custom engine.

\subsection{Writing Activation Contexts} \label{sec:writemodes} Let the reader have $L$ layers, and let $h^\ell$ be the hidden states entering layer $\ell$, so that $h^1$ holds the input embeddings. Each layer $\ell$ computes keys $K^\ell$ and values $V^\ell$ from $h^\ell$, which the KV cache keeps for later positions and turns. We write $h^\ell_{\mathrm{ac}}$, $K^\ell_{\mathrm{ac}}$ and $V^\ell_{\mathrm{ac}}$ for their $m$ rows at an AC position. An encoder maps the part's input $c$ to a write $A = f_\phi(c)$, and the three write modes differ in which of these $A$ sets (\cref{fig:overview}b): \begin{align} \text{Input Embeddings:}\quad & h^1_{\mathrm{ac}} = A^1, \label{eq:input}\\ \text{Hidden Residuals:}\quad & h^1_{\mathrm{ac}} = A^1,\ \ h^\ell_{\mathrm{ac}} \mathrel{+}= A^\ell, \label{eq:residual}\\ \text{All-Layer KVs:}\quad & (K^\ell_{\mathrm{ac}}, V^\ell_{\mathrm{ac}}) = (A^\ell_K, A^\ell_V)\ (\text{all } \ell). \label{eq:kv} \end{align} Hidden Residuals add $A^\ell$ only at a few selected layers $\ell$, and All-Layer KVs write every layer. In the first two modes, the reader prefills the $m$ rows as it does text tokens, so their keys and values are computed by the reader from $A$ and the preceding context. In All-Layer KVs, the encoder produces the keys and values of every layer directly, and the reader skips the prefill of the rows. Since later positions read the rows only through attention, that is, through $K^\ell_{\mathrm{ac}}$ and $V^\ell_{\mathrm{ac}}$, any write of the first two modes induces keys and values that an All-Layer KV write could set directly; Input Embeddings are in turn Hidden Residuals with no selected layers. This expressiveness comes with two constraints. The encoder must produce keys and values in the shape of every reader layer, for example with a head per reader layer, or as a copy of the reader with a different LoRA adapter (ours). Further, the reader must be a pure attention model: hybrid readers such as Qwen3.5 also carry the rows through recurrent layers, whose states KVs cannot set. KVs can also have a different number of rows in each layer (non-uniform KVs), as in our corpus compression experiment; $m$ is then the average over layers. Non-uniform KVs give a better representation, at the cost of more complexity and a harder integration with inference engines, whose caches assume the same number of positions in every layer. \Cref{tab:writemodes} summarizes the modes.

\subsection{Engine Implementation} \label{sec:engine} \textbf{Overview.} The engine serves the reader and the AC encoders together. For each request, it encodes the AC parts of new messages, applies each part's \texttt{ACWrite} (\cref{lst:engine}) during prefill according to \cref{eq:input,eq:residual,eq:kv}, and then decodes as usual. To support RL, its training code exchanges the updated weights with its inference code so that rollouts can use the latest ACs. Each exchange gives an encoder a new version, which invalidates its cached outputs.
\textbf{KV cache correctness.} An AC part is encoded when its message is first submitted, and its writes are applied during the prefill of that turn. Afterwards, the cache at the part's rows holds keys and values that already reflect the writes, so later turns reuse it as they reuse the cache of text tokens. Writes never apply to rows that are already in the cache, since that would invalidate every position after them. A harness that wants to change an AC, for example to re-compact a longer history, places a new part, as it would with new text, and truncates the old trajectory.

\section{Related Work}
\textbf{Harness design and harness/model co-design.} Automated harness design keeps the model fixed and searches over agent code or workflows \cite{hu2024automateddesignagenticsystems, zhang2024aflowautomatingagenticworkflow, zhang2025darwingodelmachineopenended, lee2026metaharnessendtoendoptimizationmodel} or over prompts \cite{agrawal2026gepareflectivepromptevolution}; Tressoir unifies online, offline and human-in-the-loop design and evolution of multi-agent systems \cite{ngom2026tressoirunifyingonlineoffline}. Agent post-training instead fine-tunes or RL-trains the model inside a given harness \cite{chen2023fireacttowardlanguageagent, pan2025trainingsoftwareengineeringagents, jin2025searchr1trainingllmsreason}. Joint methods alternate weight updates with harness search \cite{kim2026whalesimplerecipejoint} or optimize weights and prompts together \cite{soylu2024finetuningpromptoptimizationtwo, bo2026promptparametercooptimizationlarge}. All of these change code, prompts or weights but keep the token interface. ACs add AC encoders and write modes to this design space and are complementary; our reader model also has a LoRA adapter.
\textbf{Multimodal and structured-data encoders.} Multimodal models \cite{li2023blip2bootstrappinglanguageimagepretraining, liu2023visualinstructiontuning} and models for graphs, tables, point clouds and molecules \cite{perozzi2024letyourgraphdo, su2024tablegpt2largemultimodal, xu2024pointllmempoweringlarge, liu2023molcamoleculargraph} connect a side encoder to the language model for each input modality. Most write the encoder's outputs to the input embeddings; Flamingo instead adds gated cross-attention layers \cite{alayrac2022flamingovisuallanguagemodel}, and Qwen3-VL also adds visual features to the hidden states of the first three LLM layers \cite{bai2025qwen3vltechnicalreport}, similar to Hidden Residuals. ACs apply this mechanism to the harness's own data, with encoders declared by the harness.
edited\textbf{Compressing context into latent values.} Context compressors train a model to turn text into a few tokens, vectors or per-layer keys and values that it then conditions on \cite{mu2023learningcompresspromptsgist, ge2024incontextautoencodercontextcompression, zhang2024longcontextcompressionactivation}, or to read a small encoder's output through cross-attention \cite{yen2024longcontextlanguagemodelingparallel}. Closest to our experiments are xRAG, which maps a retriever's embedding of each document into the model as one token \cite{cheng2024xragextremecontextcompression}, as in our retrieval QA setting, and LLoCO, which compresses long contexts offline and adds in-domain LoRA fine-tuning \cite{tan2024lloco}, as in corpus compression. Each method fixes the encoder, what it compresses and where the result is written; with ACs, the harness makes these choices,choices at any turn of an agent trajectory.turn.

\textbf{Trained, fitted and evicted KV caches.} Prefix-Tuning, Cartridges and Attention Matching learn or fit compact KVs for a fixed task or document \cite{li2021prefixtuningoptimizingcontinuousprompts, eyuboglu2025cartridgeslightweightgeneralpurposelong, zweiger2026fastkvcompactionattention}. All-Layer KVs include this case (our corpus compression experiment refines the Attention Matching fit by gradient descent) and add KVs computed online by AC encoders. Methods that shrink an existing cache by evicting entries \cite{zhang2023h2oheavyhitteroracle, li2024snapkvllmknowslooking, kim2025kvzipqueryagnostickvcache} are orthogonal.
