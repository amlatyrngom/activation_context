   450	    The AdamW kept under `key` (one per adapter / AC model), created on first use and reused across
   451	    rounds so the moments and the step counters survive a round boundary (a fresh AdamW every round
   452	    would make each round's first steps sign-like updates at the full learning rate). Its moment tensors
   453	    are moved to `device` (park them on the host with `optimizer_state_to` between rounds). Rebuilt with
   454	    a note when the parameter objects differ from the stored optimizer's (an adapter re-injected).

   492	def cycle_span(updates_done: int, cycle_updates: int, total_updates: int | None = None) -> tuple[int, int]:
   493	    """schedule="cyclical": (start, length) of the cycle that holds the update about to be applied (`updates_done` are done). Cycles start
   494	    at the multiples of cycle_updates, so no boundary moves when the plan changes; the last one runs to total_updates (it takes the
   495	    remainder, and any update past the plan). Without total_updates every cycle has cycle_updates."""
   496	    count = max(1, total_updates // cycle_updates) if total_updates else None
   497	    index = updates_done // cycle_updates
   498	    if count is None or index < count - 1:
   499	        return index * cycle_updates, cycle_updates
   500	    start = (count - 1) * cycle_updates
   501	    return start, total_updates - start
