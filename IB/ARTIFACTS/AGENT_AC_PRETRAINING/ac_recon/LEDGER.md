## 07:20 UTC — code review (user request 06:50) and the silent-phase cause

- A reviewer subagent read the trainer, AC model, study generator, module manager and bench (12 findings + throughput notes; full text in the session). Confirmed against R0F's checkpoints on node 3: **the scalar gates drift at Adam's fixed ~1e-4 per step**. `target_head.scale` (the rows' magnitude relative to the reader's embeddings) started at the embedding RMS 0.0128 and the encoder had to grow it to 0.080 (epoch 1) and 0.191 (epoch 2) — a 15× climb of ~1,500 updates before the rows were loud enough to be read. That is the "silent phase" and its replicate variance. The mixers' `residual_scale` collapsed to ~0.003 (the mixer is bypassed; the side decoder carries the encoding). `position_scale` 0.1 → 0.063, `input_scale` 0.013 → 0.015.
- Fixes on snapshot `ac-recon-20260916T071339Z` (trainer): `learning_rate_gates` puts the scalar gates in their own Adam group (bench key `gate_lr`; None keeps the old behaviour); a frozen reader (lr 0 or inside the freeze window) no longer contributes to the clipping norm (its grads are dropped before clipping; the encoder was being scaled by the reader's norm); per-group pre-clip norms `grad_norm_ac` / `grad_norm_reader` and a `gate_trace` (every 25 updates) in the stats; TF32 matmuls on CUDA (the LoRA path runs fp32 GEMMs). Tests: `test_gate_group_and_frozen_reader_clipping`; the batch-equivalence test is now seeded (it flaked once at 1.8e-4).
- Snapshot `ac-recon-20260916T071846Z` (architecture, default off): `row_head_skip` (RowHead = RMS-normalized x + FFN(x), FFN output zero-initialized, so rows start as the side state itself — review finding 2), `side_lora_target_modules` + bench `lora_targets_extra` (finding 4: Qwen3.5-4B has 24 Gated DeltaNet layers whose `in_proj_qkv/in_proj_z/out_proj` no adapter touched — both LoRAs could only change token mixing in the 8 full-attention layers), bench `fresh_initial` (seeded new adapters for architecture arms).
