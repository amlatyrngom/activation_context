## What changed

- **M0, prototype changes.** `AgentConfig.env_setups` is a real field (class plus kwargs, serialized like tools) and `Agent.agent_env` runs every setup once when the env is created; subagents share the prepared env. `AgentEnvSetup` has a small contract with two reusable setups: `WriteFilesSetup` (literal text or a task-datum field to a path) and `CopyTreeSetup` (a local tree into the sandbox through the new `AgentEnv.copy_in`, a podman cp). `tools[name] = None` removes a default tool. The general `subagent` is a default tool: without `base_config` it inherits the caller (model, tools, budgets, dataset task, image), appends a focused-subagent note to the system prompt, removes every delegation tool from the child and carries no setups; its description holds the concise pattern guide and the task parameter asks for the TASK / CONTEXT / TO PRODUCE / DON'T DO brief. `dataset/environments/default.py` renders the richer default image (git, ripgrep, jq, build tools; numpy, scipy, pandas, sympy, matplotlib, networkx, scikit-learn and friends) as a content-addressed Dockerfile under ENVIRONMENTS/, and image builds are serialized across rollout threads.
- **M1, suite.** `DatasetTask.env_setups` carries a serializable setup spec. `task_framing.py` holds the minimal framing and two or three guided framings per family (multihop, math, repo, longdoc, search) with the scorer's answer rule; loaders sample one per task with a seeded RNG and record `framing_id` in the datum. New loaders: HotpotQA (distractor) and MuSiQue with the questions' paragraphs as the corpus and F1 scoring; QuALITY (letter exact match) and NarrativeQA (F1) with the document written to `/workspace/document.txt` by a setup and each document indexed for search; LongCodeArena bug localization with the base commit fetched as a GitHub tarball into REPO_CACHE, copied to `/workspace/repo` by a setup, the repository's text files indexed, exact match on any changed file path. DAPO math gains seeded framing sampling (the original prompt without a seed). `suite.py` registers the seven benchmarks with budget shares, turns BRIGHT's labeled queries into unscored research tasks, and builds oracle configs (defaults plus subagent, semantic search over the task's dataset, the task's setups and prompt). Cache keys of task runs now include a digest of the prompt, model and adapter, so a framing is a distinct run and identical configs stay free.
- **M2, probe.** `activation/agent/teacher_campaign.py` runs the suite on the oracle (`unsloth/Qwen3.8-27B-NVFP4`, whose engine table entry now allows 52k tokens) in one concurrent rollout call per pass, uncached then cached, under one caching id, with a live rollout page per pass and, at the end, `PROBE_REPORT.tressoir.md` plus `probe.json`: per-benchmark statistics, per-run lines, and the most compaction-, subagent- and search-heavy runs as excerpts. Run results gained `tool_call_counts()` and `totals()`; the rollout page's stats line shows tool counts.
- **M4 so far, reorganization and throughput (2026-09-10).** Loaders emit bare prompts with `task_kind`; the teacher framing is a template chosen by `(task_kind, teacher_kind)`; `AgentTrainingStudy` and `generate_agent_teacher_trajectories.py` replace `suite.py`, `task_framing.py` and `teacher_campaign.py`. Rollout manager: per-GPU pool, round-robin replicas, warm-up, engine stat logger, host sampler, autotune by id (probe on the first N finished, in-place pool resize, deferred reload), wall-clock deadline, indexes built once under a lock, no repository index; the reporter writes a per-benchmark summary; prompts above 20k characters are offloaded to a file in the sandbox. Tuning runs `ac-4a-tune` and `ac-4a-tune2` (804 rows each, seeds 0 and 1) measured the defaults and saved `campaign_27b_medium_v2`; `TUNING_REPORT.tressoir.md` has the numbers. Later the same day: `AgentTeacherKind` moved into the prompts module and every template became a full triple-quoted text with a single `{task}` slot (the tools note is gone; the semantic_search description says what it said); the rollout cache keys a labelled task by `<dataset>/<task>/<template>` so a caching id survives prompt rewording, like an autotune id; the campaign duration cap defaults to 1,800 s. Parallel templates reworded to delegate-and-synthesize after a parallel-only smoke run showed zero delegation under the old wording; the parallel_tool_call tool now reads flattened nested-call arguments (`{"name": "subagent", "task": ...}`) and drops nulls, the subagent tool refuses a missing brief with a tool error, and the long-prompt offload passes a None prompt through (`test_basic_tool_call_shapes.py`).
- **Campaign mix (2026-09-10 evening).** Scoring kinds `MATH_VERIFY` (math-verify equivalence, normalized-string fallback; `math-verify` added to the lock) and `UNSCORED` (`DatasetTask.score()` returns None; reporters and the tuner skip None scores; BRIGHT uses it, no judge runs in the pipeline). New loaders: DeepMath-103K at difficulty 6 and above (57,630 problems, math answer rule covering numbers, LaTeX expressions, sets, Yes/No), LOFT text RAG (five datasets at 128k and 1m, 1,100 tasks, passage collection copied into the sandbox), Loong English (695 multi-document instances, unscored). LCA runs its Java and Kotlin configs alongside Python. HotpotQA and QuALITY stay loadable but carry no campaign weight.
- **Teacher campaign and redo (2026-09-11).** 12 h run plus a redo pass of the multi-agent rows cut by budgets (60 min, 250 calls, 16 agents per GPU): 4,279 unique trajectories. `RedoPolicy` and the `--redo-*` flags; persistent draws (`draw_tasks.jsonl`, `draw.json` guard, head bootstrap from an existing cache); parallel LCA checkout prefetch with per-checkout locks and a symlink-safe tar filter.
- **Agentic programs (2026-09-14, `AGENTIC_PROGRAMS.tressoir.md`).** `AgentConfig.agentic_program`, `Agent.run_program` as the manager entry, `run_tool` / `run_subagent` / `augment_context` / `set_final_answer`, lenient deserialization through `MissingClass` placeholders (`activation/common/utils.py`), the program segment in the cache key, `score` defaulting to `None`.

## Review and differences from the plan

- The oracle used no subagent in 35 runs although the tool was in every prompt (verified by decoding a cached prompt) and 14 framings asked for delegation; it never used parallel_tool_call either. This is the main finding for D7 and for the subagent bucket of the AC items; the report ends with questions on it.
- Drifts from the plan: DeepScaleR is not in the suite (its loader in the source is a docstring stub), so math is DAPO alone; RepoQA is not implemented (its data is not retrievable), bug localization carries the repository family; repositories are fetched as GitHub commit tarballs instead of git clones (the node image has no git, and no history is wanted in the sandbox); the general subagent keeps the caller's dataset task so semantic search and setups resolve, instead of clearing it; `tools[name] = None` removes a default tool; a build lock serializes image builds across rollout threads; the run-result counters (`tool_call_counts`, `totals`) were added for the report.
- The first probe launch ran benchmarks one after another (five agents at a time); it was cancelled by job id and the runner now issues one rollout call for the whole suite.
- Turn budget, changed after your review of the probe: `max_turns` is now the total over the run (`AgentRunResult.total_turns()` sums the compaction segments; the per-turn sampling seed follows the same count), the suite and probe defaults are 100 turns, and the probe runs the scored benchmarks only unless BRIGHT is named. The probe v2 numbers were produced under the old per-segment 40-turn budget.
- Deferred with ORCD: this delta does not implement distributed training, `orcd.py` or Apptainer. The DDP work (M3) starts after your review of this round.
- From your probe review: a byte-identical repeat of the previous turn's calls (after argument normalization) is not run; the model gets a note and the turn counts as a tool error. `submit_answer` without an answer is refused. Tool argument names are normalized through per-tool alias tables plus a lone-unknown-key rule; the trajectory keeps the model's original call. The 27B engine context is 64k so an 8k thinking turn fits under the 50k cap. The cache key now includes the call kwargs, so the same task under another reasoning effort is another run (the v2 cache no longer matches, as intended).
- The repeated-call note does not cure non-thinking degeneration (base still looped in 9 runs and ended them at max_tool_errors); thinking does. The choice of oracle mode for the campaign is yours: medium effort is the strongest and slowest, low is close at two thirds of the tokens.
- 2026-09-14: the agentic-programs round added `agentic_program.py`; the unrelated local `agent_programs.py` prototype note is preserved; the activation-content design (parts with the frame, produced always, rendered by the reader) changed the part convention from 3b, so corpus rows and new rows differ in stored format until a training decision settles the upgrade.
