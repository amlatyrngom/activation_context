# Agent training canon

## Scope and data

- **Intent — Slice 2 supplies interfaces for harness–model co-design.** Problem counts, round counts, evaluation protocols, and paper experiments remain caller decisions. The implementation supports teacher data; teacher generation is an outer loop. The AC model is deferred to slice 3/4.
- **Invariant — Training preserves the token history used during sampling.** The agent owns the initial prompt tokens and appends sampled assistant tokens verbatim plus dialect-rendered tool/user wrappers. `ModelDialect` derives wrappers with a sentinel render and removes a duplicated end-of-turn token. One trajectory becomes one sequence; only assistant tokens carry loss. Fresh template rendering can rewrite prior thinking blocks and must not replace the recorded prefix. Source: `activation/agent/agent_utils.py`, `agent.py`, and `agent_training/agent_training_utils.py`.
- **Decision — Selection assigns weights; one trainer consumes them.** Group-mean advantage is the default, dropping uniform groups; RAFT positives, weighted positive/negative, and rejection variants share the clipped importance-ratio surrogate. Subagents inherit trajectory-level credit by default. `AgentTrainingItem` names the target model/adapter and weight; group keys are generated by selection. Teacher/hinted items use `ignore_logprobs`, recomputing old probabilities from the current policy before updates.

## Adapter and GPU lifecycle

- **Decision — Saving and exchanging an adapter are separate operations.** `save_lora` writes a flat PEFT checkpoint under `LORAS/<name>/round_NNN` and refreshes `latest`; `exchange_lora` publishes that checkpoint to subsequent engine requests with a new integer LoRA id. `branch_lora` copies a saved adapter. Registering an adapter alone does not apply it to the serving engine.
- **Invariant — Requested adapter and applied adapter have different meanings.** `AgentConfig.lora_name` names the requested adapter; `AgentRunResult.lora_name` records the adapter actually used by the first engine turn. Before the first exchange the result is `None`, even when the config names an adapter. Preserve this distinction in serialized results and caches. The round loop is synchronous; exchange belongs between rollout phases.
- **Decision — Engine and trainer share the GPU through sleep mode.** `engine_to_device("cpu")` sleeps the engine at level 1; moving to target wakes it and resets the prefix cache. The Transformers model vacates the GPU before wake, and freed CUDA allocator blocks are released. Freeing the engine remains a separate operation. Source: `activation/harness/loaded_model.py`, `vllm_wrapper.py`, and `module_manager.py`.

## Training and output limits

- **Technique — Keep the output head's logits and the probability-ratio math in fp32.** bf16 logits alone introduced clipping at step 1. The head's GEMM runs with bf16 operands and fp32 accumulation and output (`torch.mm(out_dtype)`: the same products as the fp32 GEMM, on the tensor cores; `fp32_head_matmul=True` is the SIMT reference), in chunks whose log-softmax is checkpointed. The base is frozen, dropout disabled, adapter gradients accumulated across micro-batches. Gradient checkpointing is by length: recompute only from `gradient_checkpointing_min_tokens` (6,144 on cards with at least 80 GB, always below that); a 12k-token row does not fit without recompute even on 96 GB.
- **Decision — One example per micro-batch with no padding mask is the default.** The Qwen3.5 profile favored this over padded packing and over packed rows (single rows are as fast or faster at every length on the RTX 6000 Pro); length rounding remains 1. `flash-linear-attention` supplies the gated-delta-net kernels on the GPU. Packed rows (`pack_micro_batches`) are exact only with the spacer tokens `collate` inserts (the gated-delta conv reads across a boundary otherwise) and the hybrid mask dict `packed_attention_masks` builds; they stay a configuration option.
- **Procedure — Every GPU type needs fla's tuned kernel configs checked in, or training stalls.** fla's Triton autotune re-benchmarks its l2norm kernels for every new sequence-length bucket (about 14 s each, in every process: 51 s of a 75 s step before the fix) because its config cache is off by default and it ships no configs for our GPUs. The trainer (`agent_training/fla_cache.py`) loads `activation/agent_training/fla_configs/<GPU name as fla sanitizes it>/*.json` in fla's fuzzy mode and prints `AgentTrainer - no fla kernel configs for this GPU` when the folder is missing. For a new GPU type, run the dump probe once on a node with the cached rollouts (`uv run sky exec --sync <node> -- uv run python -m activation.bench.agent_probes.fla_config_dump --cache-file TMP/profile_cache/agent_training_test_r0/rollouts.jsonl`; the probe lives in the tree or, if not copied in, at `IB/ARTIFACTS/AGENT_ROLLOUTS/slice2_delta/probes/activation/bench/agent_probes/fla_config_dump.py`), then copy `IB/TMP/SYNC/FLA_CONFIGS/<GPU>/` into `activation/agent_training/fla_configs/<GPU>/` and check it in. Re-run it after a `flash-linear-attention` or Triton upgrade. Verification: the step lines' `slowest` micro-batches show nothing over a few seconds after the first step, and `TRITON_PRINT_AUTOTUNING=1` prints no autotuning.
- **Invariant — Keep downstream tool-output payloads bounded.** Sandbox return text retains 4 million characters of head/tail; activation context and sandbox output files retain about four times the 20,000-character model-visible limit, plus truncation notices. The current sandbox cap is applied after `communicate`, so it bounds retained downstream payloads, not transient subprocess capture memory. Source: `activation/agent/agent_env.py` and `agent_tools.py`.
- **Convention — Detailed tests and probes stay in IB.** The slice-2 main-tree test exception is `activation/tests/test_basic_agent_training.py`; the dialect test, LoRA engine probe, training profile, engine-contention probe, stall probe and the fla config dump remain in the IB staged trees (`slice2/`, `slice2_delta/probes/`).
