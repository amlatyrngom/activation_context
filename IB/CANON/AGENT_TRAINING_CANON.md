# Agent training canon

## Scope and data

- **Intent — Slice 2 supplies interfaces for harness–model co-design.** Problem counts, round counts, evaluation protocols, and paper experiments remain caller decisions. The implementation supports teacher data; teacher generation is an outer loop. The AC model and its separate distillation trainer are described in [AC canon](ACTIVATION_CONTEXT_CANON.md).
- **Invariant — Training preserves the token history used during sampling.** The agent owns the initial prompt tokens and appends sampled assistant tokens verbatim plus dialect-rendered tool/user wrappers. `ModelDialect` derives wrappers with a sentinel render and removes a duplicated end-of-turn token. One trajectory becomes one sequence; only assistant tokens carry loss. Fresh template rendering can rewrite prior thinking blocks and must not replace the recorded prefix. Source: `activation/agent/agent_utils.py`, `agent.py`, and `agent_training/agent_training_utils.py`.
- **Decision — Selection assigns weights; one trainer consumes them.** Group-mean advantage is the default, dropping uniform groups; RAFT positives, weighted positive/negative, and rejection variants share the clipped importance-ratio surrogate. Subagents inherit trajectory-level credit by default. `AgentTrainingItem` names the target model/adapter and weight; group keys are generated by selection. Teacher/hinted items use `ignore_logprobs`, recomputing old probabilities from the current policy before updates.

## Adapter and GPU lifecycle

- **Decision — Saving and exchanging an adapter are separate operations.** `save_lora` writes a flat PEFT checkpoint under `LORAS/<name>/round_NNN` and refreshes `latest`; `exchange_lora` publishes that checkpoint to subsequent engine requests with a new integer LoRA id. `branch_lora` copies a saved adapter. Registering an adapter alone does not apply it to the serving engine.
- **Invariant — Requested adapter and applied adapter have different meanings.** `AgentConfig.lora_name` names the requested adapter; `AgentRunResult.lora_name` records the adapter actually used by the first engine turn. Before the first exchange the result is `None`, even when the config names an adapter. Preserve this distinction in serialized results and caches. The round loop is synchronous; exchange belongs between rollout phases.
- **Decision — Engine and trainer share the GPU through sleep mode.** `engine_to_device("cpu")` sleeps the engine at level 1; moving to target wakes it and resets the prefix cache. The Transformers model vacates the GPU before wake, and freed CUDA allocator blocks are released. Freeing the engine remains a separate operation. Source: `activation/harness/loaded_model.py`, `vllm_wrapper.py`, and `module_manager.py`.

## Training and output limits

- **Technique — Keep the output head's logits and the probability-ratio math in fp32.** bf16 logits alone introduced clipping at step 1. The head's GEMM runs with bf16 operands and fp32 accumulation and output (`torch.mm(out_dtype)`: the same products as the fp32 GEMM, on the tensor cores; `fp32_head_matmul=True` is the SIMT reference), in chunks whose log-softmax is checkpointed. The base is frozen, dropout disabled, adapter gradients accumulated across micro-batches. Gradient checkpointing is by the resolved `gradient_checkpointing_min_tokens`; explicit thresholds win. Automatic thresholds require a compatible whole-model memory profile, otherwise recomputation stays enabled. The historical 6,144-token threshold was a specific large-card/model measurement, not a rule for every model on an 80 GB card; a measured 12k-token row did not fit without recompute even on 96 GB.
- **Decision — One example per micro-batch with no padding mask is the default.** The Qwen3.5 profile favored this over padded packing and over packed rows (single rows are as fast or faster at every length on the RTX 6000 Pro); length rounding remains 1. `flash-linear-attention` supplies the gated-delta-net kernels on the GPU. Packed rows (`pack_micro_batches`) are exact only with the spacer tokens `collate` inserts (the gated-delta conv reads across a boundary otherwise) and the hybrid mask dict `packed_attention_masks` builds; they stay a configuration option.

- **Invariant — Keep downstream tool-output payloads bounded.** Sandbox return text retains 4 million characters of head/tail; activation context and sandbox output files retain about four times the 20,000-character model-visible limit, plus truncation notices. The current sandbox cap is applied after `communicate`, so it bounds retained downstream payloads, not transient subprocess capture memory. Source: `activation/agent/agent_env.py` and `agent_tools.py`.
- **Convention — Detailed tests and probes stay in IB.** The slice-2 main-tree test exception is `activation/tests/test_basic_agent_training.py`; the dialect test, LoRA engine probe, training profile, engine-contention probe, stall probe and the fla config dump remain in the IB staged trees (`slice2/`, `slice2_delta/probes/`).

## Shared execution configuration

- **Decision — Task getters own execution settings.** `activation/autotuners` is agent-owned, including interfaces. Agent and AC trainers pass existing model/training configs to `get_agent_training_autotuning_variables` or `get_ac_training_autotuning_variables`; only unavailable device/resource constraints need optional inputs. Autotuners derive hardware/software/kernel geometry and cache identity. Keep objectives, weights, optimizer, learning rates, compression ratio and effective batches caller-owned. Source application and current validation are tracked in STATE.
- **Invariant — Explicit values win; provenance is honest.** `None` requests automatic checkpoint/logits resolution. Preserve explicit 0 thresholds and independent checkpoint enable flags. Label conservative heuristics separately from measured profiles; kernel correctness or timing does not establish whole-model memory safety. Returned stats report resolved values and provenance.
- **Decision — Shared, immutable validated records precede committed presets.** Use `resolve_path("AUTOTUNE")` for cross-node reuse and `activation/autotuners/configs` for small promoted JSON. Exact relevant environment, geometry, semantics, schema, payload integrity and current legal native candidates gate reuse. Legacy GPU-name JSONs are seeds to validate. A hit performs no tuning; another node may still compile local binaries. Use the package's inspect/retune/promote entry point; never restore the manual fuzzy dump-and-copy workflow.
- **Constraint — Cold tuning is synthetic and bounded.** Target 60s for a whole request, extending to 180–300s when compilation or useful coverage justifies it. A separate worker owns synthetic tensors/RNG; publish a complete validated baseline before optional short searches. Reap its process group on timeout, retain completed profiles and fail explicitly when required coverage is unavailable. Model metadata is locally available after harness registration; CLI metadata preparation precedes the tuning budget.
- **Invariant — Native FLA application cannot start a hidden sweep.** Preserve current Config objects, pruning and hooks; scope the instance-local bridge across every trainer model call, including AC eval-first and sample prefill. Exact semantic coverage overrides incomplete native keys. Only demonstrated independent-row/batch axes may reuse settings; broad numeric fuzzy matching is excluded. Separate scope ownership from callback locks so autograd worker threads can execute backward. Pinned FLA's import-time architecture decisions require homogeneous visible GPU architectures.
